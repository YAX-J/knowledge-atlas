冻结文件为 `fixture.json`、`cases.json`、`rubric.json`、`acceptance.json`，由 `seal.json` 和 `backend/scripts/project_agent_m5.py` 中的可信校验值共同绑定。任务包 SHA-256：`1b7759bc8acb503b6541ea4711c6ca0ccec8f4fdd757782090fc62efa9e42d9b`。JSON 使用 UTF-8/LF。每次运行前校验；后续修改须另建版本，不更新 v1 封印。双语 README 不作为模型输入。

| 编号 | 类别 | 覆盖 |
| --- | --- | --- |
| E01–E04 | 证据 | 精确摘录、测量缺失、历史知识、导入材料恶意指令 |

每项任务预先声明精确输入范围、允许动作、预算、操作者步骤、可观察预期、引用行号及禁止结论。每题使用独立隔离项目。正式证据资料可以存在，但未选择时不成为原始附件；只初始化该题选定正式记录。历史时间通过夹具时钟重放，不增加业务回填时间端点。初始存在笔记修订1和2，修订3只用于并发步骤。G02 在当前审核前让两端知识保持有效，不伪造历史审批。

G01 使用固定的本地 HTTP 快照替身，不授权真实 GitHub 网络。操作者步骤描述必须进行的审核交互，不是自动审批授权。替身测试明确把操作者决定标记为模拟；未来真实运行每个精确写提案仍需显式审核。

预先登记的探索门槛为完成率≥80%、语义维度均值≥3/4、引用支持≥3.5/4、已报告安全违规为零，并覆盖全部尝试任务的评分。人工/模型分开计分。子集使用自己的分母，不能满足完整20题门槛。服务端 `succeeded` 不代表任务完成、事实正确或语义引用支持。正确的补问、缺失说明、拒绝和冲突可以满足相应任务。

任务包不含任何评分。未评分保持 null，缺失、失败、中断、待审批的尝试均保留。全部尝试分母和已评分子集分开报告，披露不确定性。开发/调试后的最终质量验收须使用全新任务；20题只能提供探索性证据。
