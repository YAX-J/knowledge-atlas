# 原生千级/万级读取与索引规划测量

[English](README.md)

2026-10-29 在本机 PostgreSQL 17.10 / pgvector 0.8.7 执行。[原始样本](native-scale-v1.json)每操作包含 20 次温缓存测量，另排除一次预热。各规模使用迁移后的自有临时 schema 并清理；候选经过普通显式审核/提升，每实体一份短合成来源/分块。没有供应商调用、嵌入或用户数据写入。

| 实体数 | 规划 SQL 前 → 后 | 规划 p95 毫秒 前 → 后 | Python 峰值 MiB 前 → 后 |
| --- | --- | --- | --- |
| 1,000 | 1,002 → 4 | 837.236 → 103.809 | 2.69 → 2.78 |
| 10,000 | 10,002 → 22 | 8,914.231 → 1,033.329 | 23.63 → 23.67 |

每个规模前后输出指纹一致：相同实体数和有序 UUID/文本/哈希待更新计划。证据每批 500 个实体，已有嵌入只投影元数据；内存仍线性，本次没有降低内存的结论。

| 实体数 | 关键词 p95 毫秒 /SQL | BM25 p95 毫秒 /SQL | 来源位置 BM25 p95 毫秒 /SQL |
| --- | --- | --- | --- |
| 1,000 | 1,452.514 /10 | 343.167 /13 | 399.234 /13 |
| 10,000 | 485.218 /10 | 616.456 /13 | 641.889 /13 |

这是带 Python 分配跟踪、本机并行活动与 OS/数据库缓存的测量，不是冷缓存 SLA，也不声称延迟单调增长。不含连接获取、网络/供应商和向量持久化；内存是 tracemalloc 峰值，不是进程 RSS 或数据库内存。查询使用生产作用域与 top10；万级 BM25 仍只扫描最多千级并返回截断，不能据此声称全量召回。新增 ANN 索引需要代表性时序/规范身份向量测量；结果缓存还需证据/时间/身份失效规则，这些数据不足以支持直接增加。

batch_size=32 时，全冷索引预计分别需要 **32 /313** 次嵌入请求，输入共 102,780 /1,056,780 字符；这是估算，不是实际调用或授权。未变化索引为零请求。没有 tokenizer、供应商费率与 usage 时不估金额。已有授权上限仍累计 120 模型 /160 嵌入，已使用 84/61；不得按剩余额度执行万级真实重建。

在 backend 复现：

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark_scale --output ../output/scale-new-run.json --repeats 20
```

改前算法只保留在基准脚本中用于等价/性能对比；新测量使用新目录，不覆盖本结果。
