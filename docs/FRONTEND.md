# Knowledge Atlas 前端开发说明

本文说明当前前端的结构、交互和后端接入方式。演示图谱与其中的模拟追问来自 `src/mock/data.ts`，可独立运行；项目、资料、候选审核、项目图谱和独立“证据问答”工作台使用真实后端接口。

## 技术栈

- Vue 3 Composition API
- TypeScript
- Vite
- Element Plus 图标与消息提示
- 原生 SVG 知识图谱
- CSS 响应式布局

当前图谱使用原生 SVG，是为了精确还原原型并控制节点形状、关系标签和时间状态。后续数据量超过约 200 个可见节点，或需要复杂布局、拖拽和聚类时，再评估迁移到 AntV G6。

## 启动与构建

```bash
cd frontend
npm install
npm run dev
```

```bash
npm run build
npm run preview
```

`npm run build` 会先执行 Vue TypeScript 检查，再生成生产资源。

## 当前页面状态

`App.vue` 维护以下页面级状态：

| 状态 | 用途 |
| --- | --- |
| `selectedId` | 当前选中的知识节点 |
| `timelineIndex` | 当前查看的知识时间点 |
| `visibleTypes` | 当前显示的节点类型 |
| `panelOpen` | 详情侧栏或移动端抽屉是否打开 |
| `filterOpen` | 类型筛选面板是否打开 |

时间或类型变化后，如果当前选中节点不再可见，页面会自动切换到第一个可见节点，避免图谱和侧栏状态不一致。

`App.vue` 维护项目与资料分页、当前项目/来源/任务、原文分块、候选审核、真实项目图谱、当前问答结果，以及各操作的加载/错误状态和请求序号。网络操作集中在页面；工作区组件只接收数据并发出用户意图。切换项目时清空旧问答，并使用请求序号忽略迟到响应。上传和任务执行期间阻止切换上下文，避免结果混入其他项目。

候选区域同样由 `App.vue` 管理请求、状态和迟到响应，`CandidateReview.vue` 通过资料组件的插槽展示，只接收 props 并发出意图。切换资料会使旧提取/审核响应失效；这不取消服务端已开始的提取，返回原资料后可刷新候选读取结果。默认 HTTP 超时为 30 秒，显式提取允许 240 秒，均不自动重试。

## 演示图谱交互

- 节点支持鼠标点击、Enter 和 Space 键选择。
- 当前节点使用双层酒红色描边，直接关联节点保持较高对比度。
- 项目、概念、决策、问题和代码实体使用不同形状与颜色。
- 关系标签使用等宽字体；与当前节点相关的边会高亮。
- 支持放大、缩小和重置视图。
- 类型筛选和时间轴会同时影响节点与关系。

## 项目图谱

`ProjectGraph.vue` 使用真实接口：

- 进入：资料页“项目图谱”入口，或已有项目时从导航打开。
- 查询：`GET /api/v1/projects/{id}/graph`，支持类型筛选、一跳/二跳、中心节点和返回项目总览。
- 布局：前端按节点数排成最多 4 列网格，后端不返回坐标。
- 详情：实体/关系详情展示置信度、正式写入时间和原文证据（文件名、行号、标题路径、引用）。
- 状态：没有已确认知识时提示去审核；`truncated` 时提示按类型筛选或查看邻域。
- 旧数据：已确认但未入图的旧候选可在候选区点击“补写入图谱”。

## 项目知识搜索

项目图谱中的 `KnowledgeSearch.vue` 提供关键词与独立类型筛选，只发出搜索、清空、重试和选择实体事件；`App.vue` 调用真实搜索接口并维护请求序号。切换项目、清空或新请求会丢弃旧响应。结果显示名称、摘要、命中字段、关键词排序分数及最多 3 条原文证据；该分数不表示模型置信度。无结果、截断、错误和重试均有明确反馈。选择结果打开正式详情，节点不在画布时加载其邻域并将焦点移至详情。页头仍是独立的 Mock 搜索，不会混入真实结果。

## 证据问答

`QuestionWorkspace.vue` 调用 `POST /api/v1/projects/{id}/questions`。问题限制为 200 字，单次调用允许 240 秒；页面提供空闲、加载、错误、证据支持和证据不足状态。结果展示回答置信度、关键词/向量/图关系命中数、语义索引覆盖率，以及模型实际引用的文件、行号和原文。点击引用实体会进入项目图谱、加载该实体邻域并聚焦正式详情。

问答只保留当前内存结果，不写浏览器存储，也没有历史列表。切换项目、清空或新请求会使旧响应失效。后端无证据时会直接拒答；前端不会以 Mock 内容替代失败结果。

## Mock 数据结构

核心类型定义位于 `src/types.ts`。

```ts
interface KnowledgeNode {
  id: string
  label: string
  subtitle: string
  type: NodeType
  x: number
  y: number
  size: number
  description: string
  confidence: number
  validFrom: string
  project: string
  evidenceIds: string[]
}
```

当前 `x`、`y` 和 `size` 只服务于演示布局。接入后端时，领域接口不应要求后端生成画布坐标；前端应根据返回数据计算布局，或单独保存用户调整后的视图配置。

## 响应式策略

- 桌面端使用“图谱工作区 + 详情侧栏”双栏布局。
- 中等宽度下详情侧栏变为右侧覆盖层。
- 手机端详情变为全屏抽屉，主导航移动到底部。
- 图谱保持足够大的内部画布，通过裁切显示核心区域。
- 所有主要按钮具有可见键盘焦点，并支持减少动态效果偏好。

## 接入真实 API

`src/api/` 已提供并接入项目创建/查询、本地来源仓库解析/查询、GitHub remote 身份登记、增量快照同步与 Commit 快照历史查询、项目资料分页、Markdown/Java 上传、来源查询、任务查询/执行和原文分块分页。桌面资料页分别提供单文件和文件夹入口，并显示当前项目的来源仓库清单；用户可登记 GitHub HTTPS/SSH remote，或把 remote 关联到当前页中尚未关联的本地文件夹仓库。登记只保存规范身份；每张已关联 GitHub 的仓库卡片另提供默认分支或指定 ref 的显式同步按钮，最长等待 120 秒，并展示新增、复用、未变、重命名、删除、跳过、commit SHA 与截断提示，首次成功同步后还显示稳定 GitHub ID。文件夹选择会忽略不支持类型与空文件，最多提取 50 份 Markdown/Java 文件；前端先以浏览器提供的根目录名解析稳定仓库 UUID，再剥离根目录名、顺序调用单文件接口并提交 `repository_id` 与仓库内相对路径。部分请求失败时保留成功结果并汇总失败文件。后端保存仓库身份和规范化相对路径，资料列表/详情展示仓库名称，资料标题优先显示仓库内路径，正式证据标题使用“仓库名/仓库内路径”。GitHub 导入来源的资料详情提供固定 Commit 文件外链；图谱详情、检索结果和问答引用提供固定到同一 Commit 精确行号的外链，本地来源不显示该入口。`SourceWorkspace.vue` 根据来源类型显示 MD/JAVA，并展示 Markdown 标题分块或 Java 代码/注释/类型/方法分块。已解析 Java 来源还展示类型/字段/方法卡片、同文件调用列表，以及按包、显式导入和通配导入解析的仓库内跨文件 `extends`/`implements` 与直接类型/字段接收者方法调用目标、文件和行号，并明确这些关系不是正式图谱。重复上传或同步可能返回已有任务的当前状态，不能假设始终为 `queued`；同一仓库复用来源时保留不可变内容，唯一 GitHub 重命名会更新当前展示路径，历史路径保留在快照中，相同内容位于不同仓库时保存为不同来源。普通请求默认 30 秒、GitHub 同步 120 秒超时；不自动重试创建、上传、remote 登记、同步或执行请求，结果未确认时提示刷新后重试。

启动后端 Worker 后，资料可在后台自动解析，点击“刷新状态”读取结果。手动解析与 Worker 竞争时可能返回 HTTP 409，刷新即可核对当前状态；页面尚未自动轮询任务。

通过 `VITE_API_BASE_URL` 配置后端地址。`VITE_DATA_SOURCE=mock` 默认打开演示图谱，进入真实工作区才请求后端；`VITE_DATA_SOURCE=api` 默认打开资料工作台。两种配置下，演示图谱及其中的追问保持 Mock；独立“证据问答”和项目图谱使用真实接口。后端不可用时显示错误和重试，不回退为伪造数据。环境变量修改后需要重启开发服务器。

### 候选提取与审核

已解析资料下方提供候选区域。点击“提取候选知识”前说明将原文发送至 DeepSeek；结果显示实体/关系、模型置信度、原文摘录与准确行号。支持逐项确认、拒绝、编辑名称与摘要后确认及分页。关系必须先确认两端实体。缺少密钥、模型错误、超时、证据不匹配、空结果与处理冲突均有反馈，结果不会回退为演示数据。确认会在同一事务内写入正式实体、关系和证据；旧已确认但未入图的候选可点击“补写入图谱”，不会重复调用模型或新增审核事件。

### 验证资料流程

1. 进入“我的项目”，创建一个项目，确认列表和当前项目更新。
2. 分别使用“上传单个文件”和“上传文件夹”；文件夹内准备 2–50 份 UTF-8 `.md` / `.markdown` / `.java` 及少量其他类型，核对忽略数量、上传进度、完成数量、仓库名称、仓库内相对路径、MD/JAVA 标记、原文预览与待解析状态。同一文件夹重复内容应复用首次资料及其首次路径，相同内容导入另一个根目录名时应建立不同来源，单份失败不应清除其他成功项。
3. 在“来源仓库”中登记同一个 GitHub 仓库的 HTTPS 与 SSH 地址，确认规范为同一条记录；再把另一个 remote 关联到尚未关联的本地仓库，确认显示规范 URL。对公开测试仓库同步默认分支和包含 `/` 的指定 ref，确认页面显示 commit 短 SHA、新增/复用/未变/重命名/删除/跳过统计与 GitHub ID；连续重复同步同一 Commit 时未变计数增加、资料总数不变。
4. 点击“开始解析”，核对完成状态、标题或类型/方法路径和原文行号；用两份同仓库 Java 文件确认直接类型限定调用与字段接收者调用显示目标文件/行号，重载显示多个歧义候选，参数或局部变量接收者不应被猜测；失败任务可“重试解析”。
5. 使用超过 20 个分块的文件核对翻页；重复上传同一内容应复用资料。
6. 刷新页面后再次进入资料页，确认从后端重新读取项目、仓库、资料和任务。
7. 切换到另一个项目，核对原项目资料与详情不再显示。
8. 后端不可用时检查错误与重试入口，恢复后刷新；核对文件扩展名、编码校验。
9. 在桌面宽度检查滚动、键盘焦点、长文件名、空数据和无障碍名称。分块使用文本插值，不能执行原文中的 HTML/脚本。
9. 确认实体和关系后打开“项目图谱”，核对节点/关系、类型筛选、一跳/二跳、详情证据行号和返回总览。
10. 打开“证据问答”，核对有证据回答、证据不足、错误重试、引用行号与实体跳转；切换项目后旧回答不得保留。

图谱接口、三路检索和同步证据问答已接入。演示夹具继续保留在 `mock/data.ts`；问答历史、流式输出和多轮对话属于后续开发。

接口草案见 [API_CONTRACT.md](API_CONTRACT.md)。

## 已知限制

- 独立证据问答使用真实接口，但只显示当前回答，不保存历史；演示图谱中的节点追问仍为 Mock。
- 页面刷新后默认选中返回列表中的首个项目和资料，尚未保存路由或视图偏好。
- 页头搜索只匹配 Mock；项目图谱内可切换真实关键词、语义向量和一跳图关系混合检索，并可显式更新语义索引。混合结果展示归一化组成得分及最多三条关系解释；尚无拼音或别名检索。
- 图谱节点位置固定，尚不支持拖拽、自动布局和框选。
- 真实回答质量尚未用代表性资料专项验收；自动测试中的模型响应为模拟数据。
- 当前没有组件单元测试和端到端测试脚本。
