# ADR 0042 通过审核服务重放可复现的合成实验项目

[English](0042-reproducible-curated-evaluation-projects.md)

状态：Accepted

日期：2026-10-24

## 背景

阶段六已有冻结语料和评分器，但手动准备难以复现；按当前时间提升的知识无法回答历史问题，语料指纹也不能固定已审核图谱或向量索引。

## 决策

- 增加仅依据语料编写的标注文件与独立命令 `scripts.prepare_evaluation`。要求操作者显式接受标注、全新项目 UUID、全新报告目录及 development/test/evaluation 环境。
- 复用普通来源创建、解析、待审核候选、`resolve_review`/`promote_candidate` 和演化审核。脚本不直接创建正式记录、不调用模型、不改变应用 API。
- 合成可用时间仅在独立进程的正式提升调用中重放，成功或失败均恢复时钟；不得在 API/Worker 中导入运行初始化器。候选元数据和报告标记合成历史与标注来源，不把夹具重放称为真实历史人工审核。
- 所有服务提交作为保存点包在同一外层事务内。拒绝已有项目，失败回滚整个新项目。写入前验证路径、来源覆盖、ID、证据行、同来源关系端点、历史可用性和替代顺序，提交前再次核对夹具。
- 对实际知识/证据/演化和向量索引分别计算指纹，规范化不同副本的业务 UUID。实验记录并重新核对；运行中图谱或索引变化即判失败。
- 增加 `scripts.run_baselines`，显式建立一次索引，再执行关键词/向量/混合纯检索，禁止回答生成。记录嵌入尝试/成功/失败次数、文本/字符数、逐题诊断和对比表；默认每批十条，可根据供应商限制覆盖。账单值未经取得时保持未知。
- 数据集发布 `1.0.1`，去除 `temporal-006` 的未来证据。评分协议 `line-evidence-v2` 允许正式 Schema 裁剪外侧空白，仍要求来源、行号和内部文字相等。

## 影响

同一合成已审核图谱可支持三组可复现实验和原生 PostgreSQL 验收，无需生产回填时间机制。操作者接受的标注不代表自动抽取质量。合成数据、单供应商/模型、固定权重和空白切词的中文基线限制结论；答案质量、真实仓库、工具调用 Agent 和人工评分分别推进。

## 验证

沿用用户此前选择的 Agent 执行方。命令：`python -m scripts.prepare_evaluation --dataset ../evaluation --validate-only`、初始化/实验/审核聚焦测试、完整 `pytest`、临时 schema 原生 `python -m scripts.verify_native` 和 `git diff --check`。用户单独允许本轮真实嵌入调用，DeepSeek 继续暂缓。实际结果随本轮完成记录。
