# ADR 0084：可恢复资料库与绑定原答的纠错记录

状态：已接受，已通过本地离线和隔离 PostgreSQL 验证。日期：2026-11-26。

## 决策

项目沿用既有 `archived_at`，增加显式编辑、归档和恢复接口。修改绑定 `expected_updated_at`，相同目标值可幂等重发，过期编辑拒绝覆盖。有排队/运行/待审批助手、运行/待审核协作或有效会话租约时拒绝归档。归档项目从日常列表退出，保留数据；使用归档列表获取最新版本再恢复。

新增 `source_archives` 保存资料库状态，不改来源、分块、任务或正式知识。归档从默认资料列表、代码符号搜索和本地默认相关版本集合中排除，`archived=true` 可分页查归档资料。明确选择的历史快照、原文和已有正式证据继续可读。重复上传不自动恢复归档来源，归档不撤回知识，也不阻止保留资料的显式处理。所有状态写入校验用户/项目/来源并串行使用项目锁。

新增 `answer_feedback`，仅为已持久化且成功的会话回答接收反馈。后端从保存答案取得精确结论文本和答案 SHA-256，不接受浏览器替换的答案正文。反馈按请求 UUID 幂等，冲突重发拒绝；类别和说明有界。读取只返回该用户/项目/轮次最近 50 条。反馈不改原答案、引用、正式知识、冻结数据、评测账本或论文人工评分。临时单轮答案及未保存逐结论的旧格式暂不支持该入口。

迁移 `20261126_0024` 只新增两张表，无历史业务回填。源码预期 head 为 0024；现有业务库仍为 0023，不由 API 自动迁移。升级前按备份/隔离恢复流程操作。降级只删除新增库状态与反馈，原文和知识保留；不要对业务库执行验收降级。

## 前端

项目管理和资料归档通过独立 API 模块接入工作台。写入中使用现有上下文锁；刷新项目列表更新当前项目版本，避免冲突后继续使用旧版本。纠错面板在会话已保存回答中按结论展开，失败保留同一提交 UUID；刷新只 GET，不自动重发。
