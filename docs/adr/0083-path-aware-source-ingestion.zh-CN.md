# ADR 0083：带路径上传保留独立来源

状态：已接受，本地离线验证通过。日期：2026-11-26。

## 决策

修订 ADR 0015 中与路径无关的普通上传去重规则。在同用户、项目、可空仓库和来源类型内，带相对路径的上传只有规范化路径与文件字节 SHA-256 均一致时才复用来源及解析任务。不同路径即使内容一致，也创建独立不可变来源、分块和任务。路径区分大小写；反斜杠先按原规则规范化。没有相对路径的单文件上传仍按内容去重，但只在无路径来源中查找，不与带路径来源互相复用。

使用现有 `SourceDocument` 保存文件位置与内容，无数据库迁移，schema head 保持 `20261031_0023`。项目行锁、用户/项目/仓库隔离、任务类型和返回当前状态的规则保持。修改同路径内容会创建新来源，不自动推断版本或知识替代关系。

GitHub 快照已有独立逐文件位置记录，仍允许由快照记录复用同类型 blob 和解析来源。快照文件路径与固定提交证据视图保持原契约，不以普通上传规则重写旧快照。

## 后果

本地相同内容的多个文件位置可独立列出、按路径检索、解析并定位到精确原文。重复路径不会增加任务。已有来源、分块、正式知识、证据 UUID 和冻结实验不改变。

不同路径的同内容会占用额外原文及解析存储；未来可分离内容对象和位置记录，在保留来源身份的前提下优化。历史已丢失的本地路径不能从内容哈希还原，需重新上传对应文件。无路径上传仍无法区分内容相同的不同文件名。

2026-11-26 用户选择 Agent 执行：后端聚焦 71 通过；完整后端 1139 通过、13 跳过，app 覆盖率 95.06%，满足 90% 门槛。前端 176 通过且覆盖率门槛通过，生产构建通过。系统 Chrome 1440×1000 在独立 SQLite API/前端上验证同内容文件夹的两路径保留、重复上传不增加来源、键盘打开、解析、提示及无横向裁切，截图位于忽略目录 `output/optimization-browser-20261126/source-paths.png`。外部 HTTP 被阻断；未重测原生 PostgreSQL 并发或真实模型。沙箱内 TestClient 无输出，按既有环境说明在同一虚拟环境的沙箱外完成上述测试。首次浏览器脚本在已完成流程后读取消失的焦点元素超时，修正脚本后通过，未修改产品逻辑。
