# ADR 0037：解析未限定名 Java 工厂接收者


- 状态：已接受
- 日期：2026-10-23
- 扩展：[ADR 0036](0036-bounded-java-static-factory-var-receivers.zh-CN.md)

## 背景

工厂 `var` 推断当前支持 `Type.create(...)`。静态工厂还常在当前类型中或通过静态导入写成 `create(...)`。即使仓库已经包含完整声明，这些局部变量仍保持未知，导致后续调用缺少源码链接。

## 决策

为普通方法体的 `var` 声明接受完整未限定名工厂初始化。先查找当前类型及继承成员。只要存在成员名称，就阻止静态导入回退，即使成员的参数数量或静态修饰符不能支持推断。未限定名私有静态成员只有在精确当前类型内声明时才能提供返回类型。其余情况复用显式/通配静态导入查找及显式名称优先规则。所选导入所有者缺失或成员查找截断时保持未知。

实参数量/可变参数筛选后，成员/类型限定候选必须全部为可访问静态方法。导入候选沿用现有静态导入访问规则。每个入选工厂必须返回一个可访问仓库内限定类型名，所有入选工厂必须对该名称一致。保留后续方法的原 UUID、行号范围、重复版本歧义、词法绑定生命周期，以及来源/ready/仓库边界。

当受支持的局部变量、参数或当前类型字段遮蔽限定名首段时，停止类型限定工厂推断。方法类型参数不能再被误认成同名来源类型。既有 API 形状、存储、迁移和正式知识语义保持不变。

## 影响

`var value = create()` 与 `var value = Type.create()` 都可以依据源码声明，为后续调用提供方法链接。返回信息歧义或不完整时，局部变量保持未知并继续阻止字段/类型回退。无需构建、供应商调用或自动知识写入。

本次只扩展受支持的按行识别方法体局部声明子集。通用表达式推断、实例工厂、链式/强制转换/条件初始化、`this`/`super` 工厂限定名、头部工厂绑定、重新赋值、泛型替换和按实参类型选择重载仍待后续实现。所选通配导入所有者未知时会保守降低召回。
