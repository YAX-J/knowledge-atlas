# ADR 0001 PostgreSQL 作为事实来源

[English](0001-postgresql-source-of-truth.md)

- 状态：Accepted（已接受）
- 日期：2026-10-17

## 背景

Knowledge Atlas 计划使用 PostgreSQL 和 pgvector 保存业务数据并进行向量检索，使用 Neo4j 进行图遍历。如果允许两个数据库分别独立写入事实状态，会造成确认状态、证据链接、时序状态和删除行为不一致。

## 决策

PostgreSQL 作为业务状态、原始资料、审核状态、稳定标识符和同步元数据的权威存储。

Neo4j 保存针对关系遍历优化的可重建投影。图节点和关系使用稳定的业务 UUID，而非 Neo4j 内部 ID。经过确认的 PostgreSQL 事务产生幂等的图谱投影操作。首版可以由应用直接同步，但必须保留演进到基于 Outbox 的 Worker 的路径。

## 影响

- 业务状态只有一个权威存储位置。
- Neo4j 损坏或结构变化后可以重建。
- 系统必须跟踪投影状态、重试和错误。
- 图查询可能暂时落后于 PostgreSQL 写入。
- 投影延迟影响用户时，API 响应必须明确处理。

## 评估过的替代方案

### 仅使用 Neo4j

未采纳，因为文件元数据、任务、审核流程、向量存储和事务性业务记录更适合 PostgreSQL。

### 双数据库均可权威写入

未采纳，因为分布式一致性和恢复会给毕业设计范围带来不必要的风险。

### 仅用 PostgreSQL 进行图查询

目标架构没有选择该方案，因为 Neo4j 更便于多跳关系查询和图谱演示。如果运维复杂度威胁最小可行产品交付，仍可将其作为后备方案。
