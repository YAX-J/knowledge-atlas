# ADR 0029：打包有界仓库内 Java 分析 V1

[English](0029-java-analysis-v1.md)

- Status: Accepted
- Date: 2026-10-21

## 背景

用户要求先把当前 Java 分析功能作为整体完成，再统一测试。连续的小型词法扩展仍遗漏传统 for/资源作用域，以及有用的继承/重载候选。完整 Java 编译器仍不属于当前有界源码分析架构。

## 决策

- 以 [V1 能力与验收边界](../JAVA_ANALYSIS_V1.zh-CN.md) 打包交付，不暗示完整 Java 语义。保留既有接口形状、仓库/ready/字节/结果上限、分块、持久化和已审核知识边界，不新增编译器依赖、服务、迁移或前端要求。
- 带花括号的传统 for 与资源 try 体复用词法绑定，接受传统 for 单变量声明、多个资源声明或既有引用；`var` 仅从构造器推断。头部调用继续省略，绑定随主体退出，未知绑定阻止回退。
- 沿仓库内 extends/implements 查找继承候选，使用原方法符号、规范化原始参数签名抑制覆盖，并去重菱形路径；支持继承的未限定/this/super 调用。不继承构造器、私有方法或接口静态方法，包可见方法不能越过包路径；保留来源版本与候选分支歧义。
- 同文件及跨文件调用按已知实参数量（含可变参数）筛选；屏蔽字面量时保留标记，区分空字符串与无实参。不确定表达式语法保留候选；同数量类型重载仍保持歧义，不推断运行时分派。
- 每次继承查找最多访问 256 状态，环或预算触顶报告截断。目标排序保持确定性，结果限流时不保留悬空边。
- 本决策仅对 V1 子集补充 ADR 0017 与 0022–0028。完整 AST/classpath/类型/访问检查、泛型替换、高级语法、工厂推断与运行时行为仍属独立后续工作，不自动完成阶段四。

## 影响

既有大纲可以从常见循环/资源协作者定位到继承声明，并减少明显不兼容的重载。功能包拥有一条综合 API 验收路径和统一后端回归，不再把每个微小语法补充视为整个功能完成。结果仍是有界静态候选，不是正式图谱事实或编译器认证的调用。
