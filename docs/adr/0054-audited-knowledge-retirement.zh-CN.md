# ADR 0054：保留历史知识的审计停用

状态：已接受 · 日期：2026-10-26


## 决策

允许人工以误确认纠错或已过期为由，提供必要说明并经界面二次确认，停用当前 active 实体或关系。这是新增的窄图谱修改边界，由 retirement.retire 与 graph.apply_retirement 实现，沿用审核/演化/索引写入的项目锁。迁移 20261026_0017 增加 knowledge_retirements，保存作用域组合外键、唯一种类所有者、原因/类别、生效时间及不可变前后快照。

采用服务端当前时间，原子关闭 valid_to 并写审计。保留 status、原候选/审核决定、来源/分块/证据、语义向量和 UUID。半开区间使生效时刻及之后的当前查询排除此项，之前的历史查询仍可读取。停用实体后，既有端点可见性规则会让关联关系退出当前视图，不改写关系区间。不设置会屏蔽全部历史查询的硬归档标志。待审演化建议必须重校验，不能复活已停用端点。

客户端请求 UUID 映射为用户/项目范围内确定性事件 UUID。相同提交重复返回原审计；相同 UUID 改载荷报冲突；换 UUID 再次停用已截止知识也报冲突。传输结果未知不自动重发；同一挂载工作台内明确重试相同输入会复用 UUID。写入及审计分页均保留用户/项目/项目归档边界。

## 影响

这里的纠错是让误确认内容退出当前使用；正确内容仍应经正常候选审核。不会修改旧摘要、撤销原确认、合并实体、删除证据、重新打开区间、预约未来停用或回填过去。历史视图有意保留当时的判断，不保证历史结论本身正确。迁移降级只移除审计表，不重新打开知识区间；降级前需保留可验证备份以免丢失审计。

界面共用演化写入锁；成功后清除过时检索/问答/对照状态并刷新图谱/索引状态，提供审计分页和停用前详情/证据跳转。“active”仍是历史记录状态，当前资格由 valid_to 决定。原生 PostgreSQL 竞争及浏览器验收见[记录](../OPTIMIZATION_456_20261026.zh-CN.md)。
