# ADR 0014 按需解析有界的跨文件 Java 类型关系

[English](0014-bounded-cross-file-java-types.md)

- 状态：Accepted
- 日期：2026-10-19

[ADR 0015](0015-local-folder-repository-identity.zh-CN.md) 将当前实现从项目范围收窄为有仓库身份时的仓库范围；旧的未归属来源仍在独立的未归属集合中互相解析。

## 背景

持久化的文件夹相对路径和来源级 Java 大纲已经能定位文件，但开发者仍无法看到某个顶层类型是否继承或实现了项目中的另一个来源类型。完整的编译器级符号图需要仓库标识、构建配置、类路径和更严格的增量更新语义。ADR 0015 已提供有界的本地文件夹身份，其余输入仍未具备。

## 决策

- 扩展 `GET /api/v1/sources/{source_id}/code-structure`，按需返回限定在当前来源仓库身份内的顶层类型 `extends` 与 `implements` 关系。没有仓库身份的旧来源只在所属项目的未归属集合内解析。
- 只检查同一用户、同一项目、同一可空仓库身份中状态为 `ready` 的 Java 来源，包括当前来源和最多 99 份相关来源；相关来源原文累计读取上限为 20 MiB。
- 依据 Java 源码声明、显式导入、同包查找和通配导入解析目标，不猜测无法解析的外部库类型。
- 返回稳定的目标符号 ID、来源 ID、可用时的持久化相对路径、源码行号及 `resolved` 或 `ambiguous` 状态。
- 相关类型最多 400 个，类型关系最多 500 条；来源或结果达到上限时通过既有 `truncated` 标记提示。
- 每次都从不可变的来源字节派生结果，不持久化结构，也不把它提升到已审核的正式图谱。

## 影响

来源工作台无需模型调用或新解析器依赖，就能追踪一部分有用的跨文件类型层次。仓库、项目与用户边界保持明确；当同一个包限定名存在多个声明时，系统会标记为歧义，而不是任意选择一个。

这不是完整的仓库级 Java 语义解析。它不解析嵌套类型、静态导入、模块/类路径优先级、跨文件方法调用、继承分派、依赖注入、生成源码、外部库或动态分派。本地文件夹身份基于规范化根目录名，仍弱于 Git remote 身份。

## 评估过的替代方案

- 现在就持久化代码图：推迟到仓库标识与增量同步规则明确之后。
- 在仓库范围内按唯一简单名称匹配：拒绝，因为这可能生成 Java 导入规则不允许的虚假关系。
- 现在引入编译器或 tree-sitter：推迟到更完整的跨文件方法解析足以证明其运维和语言版本成本合理时。
