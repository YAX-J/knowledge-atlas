# ADR 0087：版本化 hybrid 词法召回与配对测量

状态：已接受并完成离线回归。日期：2026-11-26。

## 决策

当前 `hybrid` 的词法分支复用已有有界全局 BM25，支持中文问题与多词软匹配；不再要求所有空白分词同时出现在文本中。仍按用户、项目、类型、正式状态与有效时间过滤。两路各最多 100 种子、一跳最多 500 边、固定 0.3/0.4/0.3 权重保持。没有使用冻结 holdout 或旧失败输出来选择权重。

搜索结果增加 `hybrid_protocol=bm25-vector-graph-v2`；问答检索摘要也保存该字段。旧记录缺少协议时按保存值读取，不重算或重新调用供应商。新 hybrid 使用 `bm25_score`，`keyword_score=null`；保留 `keyword_component` 和 `weights.keyword` 作为词法分支兼容字段，其值分别是池内最大 BM25 分数归一化结果和既有权重。输出 `lexical` 的扫描范围及截断信息，合并到总 `truncated`。前端按新协议显示「BM25 词法」。

默认字面关键词搜索、默认问答 RRF 及独立 BM25 语义保持。纯标点的 hybrid 查询现在沿用 BM25 的 422 提示；符号精确检索使用 keyword。向量配置校验、空索引零调用、供应商错误不静默回退保持。图关系信号是关联强度，不保证语义相关，也不表示答案支持性。

## 配对性能测量

新增 `python -m scripts.benchmark_lexical_batches --output ../output/<新目录> --counts 1000 10000 --repeats 3`。在隔离 PostgreSQL 内固定同一合成数据、查询和时点，分别测量读取批次 200/500；每组预热一次不计入样本。逐次断言除批次元数据外排序、分数、证据和截断指纹一致，阻断供应商，清理自有 schema。

本机 2026-11-26 温缓存、含 tracemalloc 开销的中位耗时如下（毫秒），不是 p95 或 SLA：

| 实体数 | 模式 | 200 | 500 | SELECT 次数 200→500 |
| --- | --- | ---: | ---: | ---: |
| 1000 | bm25 | 441.816 | 581.738 | 26→17 |
| 1000 | bm25_source | 477.828 | 585.511 | 26→17 |
| 10000 | bm25 | 3396.876 | 2847.683 | 161→71 |
| 10000 | bm25_source | 3937.267 | 3379.303 | 161→71 |

200/500 的输出指纹一致。Python 分配峰值分别约 1.40/1.54、1.33/1.65、7.22/7.29、7.17/7.31 MB，并非进程 RSS。500 在较大规模降低耗时，但较小规模变慢，故本轮保留固定批次 200；不据此宣布普遍性能提升。原始报告位于忽略目录 `output/lexical-batch-paired-20261126-01/run.json`，状态 succeeded，供应商调用0，自有 schema 已清理。

没有直接添加 HNSW：当前查询包含规范身份聚合和最小距离，需代表性执行计划与精确召回对照再决定索引与重写；维度仍1024。数据库级词法索引、可变维度和更大规模缓存仍是后续方案。历史性能及冻结质量报告不变，新的用例仅验证工程行为，不等于重新测得 Recall@5 或模型质量。

独立中文回归覆盖软匹配、作用域和时间过滤、空向量索引、截断与问答协议记录。隔离桌面验证键盘提交和词法贡献显示。最终测量脚本用 201 条合成实体再跑一次冒烟，两种批次的业务结果指纹一致，临时 schema 已清理。
