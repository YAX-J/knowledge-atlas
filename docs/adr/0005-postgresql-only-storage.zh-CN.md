# ADR 0005 仅使用 PostgreSQL，暂缓引入 Neo4j

[English](0005-postgresql-only-storage.md)

- 状态：Accepted（已接受）
- 日期：2026-10-17
- 替代：[ADR 0001](0001-postgresql-source-of-truth.zh-CN.md)

## 背景

用户希望使用本机原生服务，不使用 Docker，且已经安装 PostgreSQL。当前 Neo4j 只涉及配置、驱动依赖和就绪检查，尚未实现图谱数据或业务图查询。在 Markdown 到证据问答流程完成之前，维护另一个数据库及投影同步会增加工作量。

## 决策

当前只使用 PostgreSQL，并以它作为事实来源。保留 pgvector 用于规划中的向量检索。移除 Neo4j 的包依赖、配置、环境示例、就绪检查，以及可选 Compose 服务和卷声明。

后续在 PostgreSQL 中实现图谱节点、关系、证据关联、审核状态和时序状态。保留知识模型、稳定业务 UUID、`user_id`/`project_id` 边界、证据可追溯性，以及 `new knowledge -[:SUPERSEDES]-> old knowledge` 的替代方向。本次修改尚未实现这些表或真实图谱 API。

直接关系使用关联查询，限定深度的遍历可采用递归查询。查询需要范围与时间过滤、循环保护、深度/结果量限制，并根据实际查询添加索引。已确认知识及其证据和审核状态在同一事务中提交。

如果实测查询复杂度、性能或图算法需求证明有必要，可通过新 ADR 重新评估 Neo4j。届时 PostgreSQL 仍为权威存储，图谱投影沿用稳定 UUID。当前不保留闲置驱动、功能开关或同步层。

## 影响

- 本机开发和验收只要求 PostgreSQL 与 pgvector，Docker 仍为可选方案。
- 就绪接口仅返回 PostgreSQL 状态，连接正常时 HTTP 200，连接失败时 HTTP 503；它不验证迁移版本或 pgvector 是否可用。
- 图谱持久化尚未实现，无需迁移应用图谱数据。
- 已有本地 `NEO4J_*` 环境配置会被忽略，可以删除。删除 Compose 卷声明不会删除已有数据库卷或安装。
- 图查询需要设计 SQL 并验证性能；本决策不表示能在任意遍历场景下等同于专用图数据库。
- 真实图谱展示、抽取、检索和 Agent 回答仍属于后续工作。

## 评估过的替代方案

### 继续强制使用 Neo4j，或只关闭其健康检查

暂缓采用，因为业务能力尚未使用它，却仍需安装服务或保留闲置依赖。

### 换用其他图数据库或扩展

暂缓采用，因为尚无实际需求证明有必要增加安装和兼容性边界。
