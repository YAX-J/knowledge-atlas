# ADR 0085：显式预览的有界长文档分批抽取

状态：已接受，本地离线与隔离 PostgreSQL 验证通过。日期：2026-11-26。

## 决策

默认单次抽取和旧工具模式保持原协议。新增免费 `GET /sources/{source_id}/extraction-plan`，对原文精确切片并按每批最多 100 片、配置的 JSON 字符上限规划，最多 8 批/800 原分块。超长单块按换行优先切片，必要时按字符切片；不改变数据库原分块。虚拟输入片段 UUID 由原块 UUID 和精确区间生成，正式候选恢复原分块 UUID 和实际行号。

`POST .../extract?strategy=batched&plan_sha256=...` 明确确认计划后才执行。哈希绑定来源字节、片段、模型、端点、提示词版本和上限；配置变化先重新预览，不静默扩大。任务 ID 另含分批协议和计划哈希，不覆盖旧批次。最多一批一次模型请求，不使用工具循环，不自动重试或回退。已成功同计划只读返回，无新增调用。

每批先检查持久化任务执行权并续租，再请求模型；只接受该批输入内的精确引用。输出实体/关系局部 ID 在服务端隔离，关系端点随之重映射。仅当类型、名称/摘要、置信度、时间及精确原文位置等完全一致时去重；不做语义实体合并。全部批次通过原有候选、时间和证据校验后一次保存，仍需人工审核正式入图。后续批次失败不保存前面的候选，不自动续跑；显式重试会重做未发布的整轮，可能重复计费。

正式提升在验证候选建议行号确实包含该摘录后保留该位置，避免重复文本被重新定位到首个出现处；没有有效建议时沿用旧定位规则。不信任模型行号。

## 边界

不新增业务表，schema head 仍为 0024。执行保持同步，前端有 30 分钟等待上限；关闭等待不取消已发出的请求，可 GET 查看状态。跨批仅做精确去重和 ID 归并，不自动发现跨章节语义关系。超过 8 批或 800 原分块仍需按章节拆分。预算上限不代表质量或费用估计。
