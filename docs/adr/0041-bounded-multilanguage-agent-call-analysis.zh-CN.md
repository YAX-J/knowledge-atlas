# ADR 0041 通过 Agent 执行有界多语言跨文件调用分析

[English](0041-bounded-multilanguage-agent-call-analysis.md)

- 状态：Accepted
- 日期：2026-10-24

## 背景

Java 已具备保守的仓库内调用提示，而 Tree-sitter 新语言目前只提供语法大纲。为每种语言重新实现完整符号求解器超出本项目范围；把整个仓库直接交给模型又会带来成本、不可验证结果和源码提示注入风险。

## 决策

- 新增显式同步接口 `POST /sources/{source_id}/agent-call-analysis`；打开资料不会自动调用模型。
- 本地提取调用点与声明，只从同一仓库边界、状态为 ready 且语言族兼容的来源建立候选：Java、Python、JavaScript/JSX/TypeScript/TSX、Go、C/C++ 或 C#。
- 最多扫描 99 份相关来源和 20 MiB 原文，最多分析 100 个存在候选的调用，每个调用最多暴露 20 个声明候选；请求同时遵守已有抽取输入字符上限。
- Agent 只接收稳定调用/候选 ID、路径、带行号的调用上下文和精确声明行。源码属于不可信数据，不是指令。
- 输入中的每个调用必须且只能返回一条结构化决定。Agent 只能选择后端给出的目标 ID，并返回 `resolved`、`ambiguous` 或 `unresolved`、置信度和可展示的简短依据；后端拒绝缺项、重复、结构矛盾或候选范围外结果。
- 调用行与声明行证据由后端从自有原文生成。结果只是临时派生提示，不持久化、不提升，也不写入正式图谱。
- 没有仓库内候选时直接返回空结果，不调用供应商。桌面端明确显示显式费用边界，并覆盖加载、空、错误、重试、语法错误和截断状态。

## 影响

所有已支持代码语言都能复用同一安全工作流，同时不声称具备编译器级完整性。Java 保留确定性分析，并允许 Agent 对其有界候选进一步消歧。C/C++ 尤其受缺少 include path、宏配置和 `compile_commands.json` 影响；全部语言都可能遗漏生成代码、外部依赖、动态分派、反射、依赖注入、别名或依赖数据流的接收者。

这是一轮有界结构化 Agent 步骤，不是持久化多轮规划 Agent。真实供应商的质量、延迟、成本与提示注入验收独立于模拟测试；扩大预算前应使用冻结测评流程量化。

## 验证

2026-10-24 由 Agent 执行：159 项解析/调用分析聚焦测试及完整后端套件通过（552 通过、4 项显式原生/外网跳过），保留一条既有 Starlette 弃用警告；前端生产构建通过。隔离模拟 API 的 1440×1100 桌面 Chrome 走查覆盖显式触发、加载锁定、已校验结果、零候选/零供应商调用、503 错误、键盘重试、长路径、面板滚动和横向溢出，未发现应用控制台错误。未调用真实模型/GitHub/业务数据库，也未产生供应商费用。
