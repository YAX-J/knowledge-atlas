# ADR 0038：在循环与资源头部推断 Java 工厂接收者


- 状态：已接受
- 日期：2026-10-23
- 扩展：[ADR 0037](0037-unqualified-java-factory-receivers.zh-CN.md)，替代其对受支持头部工厂局部绑定的排除

## 背景

有界 Java 分析已支持带花括号的传统 for/资源 try 头部构造器初始化 `var`，以及普通方法体声明的静态工厂推断。因此，尽管已有工厂和返回类型声明，`try (var resource = Factory.open())` 及同类循环声明仍将接收者保留为未知。

## 决策

将尚未解析的 `var` 头部初始化表达式保留为内部解析元数据。词法处理到达主体左花括号时，复用方法体局部变量的静态工厂查找、实参数量筛选、可访问性、一致返回类型及已解析身份规则。头部与方法体声明按源码顺序处理；资源列表内部按声明顺序添加绑定，前面的名称会遮蔽工厂限定名，后面的名称不会影响前面的初始化表达式。

返回绑定只在受支持的花括号主体及其嵌套作用域可见，在 catch/finally 和相邻作用域前失效。头部表达式仍不产生调用边。未知/不支持的初始化保留未知绑定并阻止字段/类型回退。显式类型、构造器 `var`、增强 for 与 catch 绑定保持既有行为。

## 影响

传统 for 的单声明及资源 try 的单/多声明现在能将后续接收者调用定位到仓库内原方法 UUID 和行号。返回来源的重复版本继续保持歧义。仓库/ready 边界、输出预算、API 形状、持久化与已审核知识边界保持不变。不引入编译器、供应商、迁移或自动图谱写入。

无花括号控制语句、传统 for 多变量声明头部、带注解/复杂的不支持头部、实例/链式/强制转换/条件工厂推断、泛型替换及运行时分派仍排除。头部调用刻意省略，工厂推断仍要求相关声明已经导入。
