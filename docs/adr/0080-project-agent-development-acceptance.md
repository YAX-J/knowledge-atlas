# ADR0080: Separate engineering acceptance from project-agent quality

[简体中文](0080-project-agent-development-acceptance.zh-CN.md)

Status: Accepted · 2026-10-31 · M5 offline preparation

M1–M4 have local substitute/native/browser evidence. That does not measure general task completion or semantic citation support. Historical answer judges do not validate note edits, approvals, recovery or graph changes.

Use an independent fictional20-task development packet with four tasks in each of evidence, organization, code, notes and governance. Freeze fixture, goals/scopes, operator steps, expectations, thresholds and acceptance matrix before live calls. Pin file hashes and a trusted packet digest in code. Preserve all prior experiments/holdout/results/grants/ledgers. Any debugging-driven revision requires a new packet version; final quality work uses fresh tasks.

The M5 CLI validates, produces zero-call preflights, runs existing engineering checks and summarizes externally reported task exports/grades. It cannot run providers, create grants, approve proposals, backdate business data, push or publish. Preflight records the implementation/configuration fingerprints and shared8/16 task caps, with0 reservations/completions and0 judges. Model snapshots, monetary estimates and live compatibility remain unverified. A later authorized live executor and isolated fixture replay are separate work.

Engineering subprocesses save commands, test XML, exit codes, log hashes and fail-stop stage state in a fresh ignored output directory. A pytest transport barrier blocks real sync/async HTTP transports while retaining ASGI/local mocks; native acceptance propagates the barrier and removes only its own generated schema. Backend90% and existing frontend thresholds remain. Local evidence and hosted CI are different statuses.

Scoring binds each observation to packet/preflight and grades to exact run/observation hashes. Schema, scope, budget and quote provenance are mechanical checks. Missing exports remain in attempted counts. Unattempted cases are listed separately. Unscored completion/semantic grades stay null; partial grades expose a confirmed-completion lower bound and an explicitly graded subset. Human and model coverage, means and uncertainty are separate. Server success is not semantic completion. Partial task selections never satisfy the full-packet gate. Source provider provenance and imported grades are reported, not independently certified.

Review templates contain nulls, not manufactured grades. There is no automatic answer-judge substitution for general tasks, retry/fallback, operator approval or release certification. Scripted operator actions in tests are simulations over disposable fictional data, not human review evidence. No business schema/API/runtime change is required by this phase.
