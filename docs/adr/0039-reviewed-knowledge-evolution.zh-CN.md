# ADR 0039：显式审核跨来源知识演化


- 状态：已接受
- 日期：2026-10-23

## 决策

新增 `knowledge_changes`（迁移 `20261023_0015`）作为独立跨来源审核边界，不放松候选提升的同来源/同任务端点约束，也不伪造抽取任务。仅已确认记录是权威演化关系。普通图谱仍为时间可见语义知识；独立历史 API 展示失效端点及替代关系。

用户对同用户/项目中不同、同类型、有效的正式实体提出 `SUPERSEDES`、`SUPPLEMENTS` 或 `CONFLICTS_WITH`。须有理由和属于任一端点、仍可核验的正式证据 UUID；双方均须保留有效逐字证据。不调用模型。规范化后相同请求复用稳定 UUID。提出/拒绝不改变正式知识。

确认先锁项目，重读并重新校验建议、端点、证据及时间。正式修改仍显式集中在图谱服务：`promote_candidate` 创建抽取知识，`apply_reviewed_change` 应用人工演化。审核、不可变前后快照和端点更新同事务提交。同动作重复幂等，不支持改判。

替代方向为 **新 → SUPERSEDES → 旧**。旧有效期在 `effective_at` 截止，新有效期从此刻开始；旧状态变为 `superseded`。有效区间为半开 `[valid_from, valid_to)`。V1 拒绝未来时间及早于任一端点当前有效起点的时间，不从原文定年、不回溯提升前、不定时生效、不合并链、不支持分叉或环。锁内有效端点检查及新实体至多一个已确认前驱保证线性链。补充/冲突仅记录分类，不改变有效期或自动判断事实真假。

历史校验用户/项目及项目未归档，仅遍历已确认替代，防环且最多 100 个实体/200 条变化。图谱、搜索与问答沿用有效时间和关系双端点可见性。抽取的 `SUPERSEDES` 语义断言不会自动修改有效期，须显式演化审核。

治理只读扫描最多 1,000 个当前实体，默认返回最多 200 条建议（最大 500）：有效逐字证据缺失、规范化后同类型同名同摘要重复或不同摘要可能冲突，以及无可见语义关系/已确认演化关系的孤立节点。规范化使用 NFKC/大小写/空白；同名组与首个实体比较，不是穷举两两语义推断。结果不持久化候选或自动修复；省略标记 `truncated`。

## 影响

- 降级 `0015` 会删除演化建议/审计关系，但不会撤销已提交的实体有效期；必须先备份，不能把业务 schema 降级当作验收步骤。

- 保持抽取审核、原始证据、UUID、时间与归档过滤；演化独立于一跳语义检索。
- 前端新增历史查询、显式审核、可核对证据的时间链和只读检测；历史视图不能修改知识。
- 不增加合并/消歧、自动语义冲突推断、撤销、任意元数据修改、模型质量保证或问答持久化。
- PostgreSQL 验收必须显式指定 Alembic 版本表 schema，测试前检查全部本地表。单独使用 `search_path=temp,public` 不安全：Alembic 或查询可能回退到已有 public 表。最后只可删除自己生成的 schema。
