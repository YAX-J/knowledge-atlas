# ADR 0028：在有界异常作用域内解析 Java 调用

[English](0028-java-exception-scope-receivers.md)

- Status: Accepted
- Date: 2026-10-21

## 背景

ADR 0026 排除异常处理区域。普通 try/finally 体与显式类型 catch 参数已包含足够的词法信息，可以连接仓库内协作者而无需求解异常控制流。ADR 0027 已为增强 for 元素引入仅在块体生效的头部绑定。

## 决策

- 普通 `try` 与 `finally` 花括号块复用既有局部声明生命周期、受支持子块、未知 `var` 遮蔽及外层绑定恢复规则。
- 无注解 catch 参数复用仅在块体生效的头部绑定。单个简单或限定类型支持可选 `final`，通过既有包/导入和仓库查找解析。绑定仅存在于自身 catch 体和受支持子块，不能泄漏到相邻 catch、finally 或后续代码。
- 多异常联合类型如 `A | B error` 保留未知绑定，不任选一个分支，也不推断共同父类。该接收者不能回退到同名字段/类型，catch 内其他接收者仍可解析；显式 `this.field` 继续选择字段。
- 资源 try 的头部和主体仍排除。后续受支持的 catch/finally 独立解析，不引入资源变量。不支持的祖先和带注解 catch 仍排除；继承分派、异常路径分析、通用推断及重赋值/数据流仍待后续处理。
- 响应形状、调用/目标行、稳定 ID、仓库/来源/结果上限、来源分块、持久化及与已审核正式图谱的边界保持不变。本决策补充 ADR 0026 的异常区域排除范围，无需迁移、外部服务或前端改动。

## 影响

异常处理协作者可以在既有来源大纲中展示，同时保持明确的词法隔离。结果仍是有界语法提示，不是异常控制流分析或完整调用图。仅因接收者是 catch 参数，并不会让外部异常父类的继承方法变成仓库内目标。
