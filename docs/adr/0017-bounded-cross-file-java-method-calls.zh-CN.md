# ADR 0017 按需解析有界的跨文件 Java 方法调用


- 状态：Accepted
- 日期：2026-10-19

## 背景

来源结构视图已经能派生同文件调用和仓库范围的跨文件类型关系，但无法把常见的 `validator.validate()` 服务调用连接到另一份已上传源码中的方法。完整 Java 语义引擎还需要类路径、重载签名、继承、泛型、局部数据流和构建系统集成，超出了当前有界导入切片的规模。

## 决策

- 扩展 `GET /sources/{source_id}/code-structure`，按需返回 `related_methods` 与 `cross_file_calls`；不新增持久化表，也不写入正式图谱。
- 只检查当前仓库边界内状态为 `ready` 的 Java 来源，沿用最多 100 份来源和 20 MiB 相关源码的限制。
- 只解析两类明确接收者：`OrderValidator.normalize()` 这类遵循常规大写类型命名的直接类型限定调用，以及当前顶层类型直接字段上的 `validator.validate()` / `this.validator.validate()` 调用。
- 使用既有的显式导入、同包和通配导入规则解析接收者类型，只返回另一份来源中匹配顶层类型直接声明的方法。
- 方法只按名称匹配。唯一候选为 `resolved`；重载、重复的不可变来源版本或重复包限定类型均为 `ambiguous`。
- 最多返回 500 个相关方法与 500 条跨文件调用，保留精确调用行和目标行；因截断未返回完整目标的关系也不返回。

## 影响

桌面来源大纲现在可以展示有用的仓库内方法边，同时不修改不可变来源，也不绕过已审核知识的提升流程。目标 ID 与目标来源自身结构视图中的确定性方法符号 ID 保持一致。

这仍是语法提示，不是 Java 调用图。它不解析局部变量、参数、工厂/链式接收者、继承方法、接口到实现、静态导入、参数类型、重载选择、泛型、生成源码、外部库、依赖注入或动态分派。字段只采用声明类型，不进行数据流分析；仅远程 GitHub 仓库也没有可供分析的源码。

## 评估过的替代方案

- 立即引入完整 Java 解析器和符号求解器：推迟到代表性仓库证明有界规则不足以支撑毕业设计评估时再考虑。
- 把派生调用持久化到图谱表：拒绝，因为未经审核的解析提示不是正式知识。
- 用正则猜测局部变量和参数类型：拒绝，因为变量遮蔽与嵌套作用域会使可信边界不清晰。
