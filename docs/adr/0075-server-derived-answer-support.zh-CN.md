# ADR 0075：后端计算回答总体支持状态


- 状态：已接受
- 日期：2026-10-31
- 取代范围：仅取代 ADR 0069 中由模型生成总体 `supported` 的规定；逐条引用、证据范围、持久化与人工审核边界保持。

## 决策

新回答使用 `evidence-claims-v3`。模型顶层只能返回 `confidence`、`claims` 和 `missing_information`。`ClaimAnswerDraft.supported` 改为后端属性：仅当所有条目的 status 都是 `supported` 时为 true，且必须至少有一个条目。属性不进入模型 JSON Schema 或序列化；模型输出顶层 supported 即使一致也按多余字段拒绝。single_step 和 tools 使用同一严格格式，不回退、不自动重试。

API 仍返回 `supported`、平铺 `answer`、证据和实体 ID。混合回答总体为 false，同时保留有据条目及其精确引用；全部不足时没有引用。不足条目仍须说明缺失信息。逐条引用、UUID 去重、当前检索/项目范围、条目/文本/引用上限和额外字段拒绝规则保持。这些检查验证结构与归属，不证明语义蕴含。

v2 与平铺历史快照保持原样。`QuestionRead` 接受两种版本及 null；读取和同 UUID 重放不重算支持状态、不调用模型。`ClaimAnswerDraftV2` 仅为显式历史诊断适配器，不用于真实输出回退。无需 SQL 迁移，head 仍为 `20261029_0019`。新实验清单记录 v3；精确复用拒绝 v2 scope，不将其改标为 v3。

## 验证边界

使用[独立虚构 Nimbus 开发用例](../../evaluation/development/claim-support-v3/README.zh-CN.md)：全部有据、混合支持、全部不足、共享引用，以及非法变体。夹具不含冻结语料、题号、失败答案正文或裁判反馈。HTTP 替身覆盖两条供应商路径，并核对拒绝时只尝试一次、不重试。集成测试覆盖跨项目引用、无证据、持久化历史/重放和实验导出。

历史实验、holdout-v3、授权/账本、原始输出、指标、排除清单与裁判报告逐字节保留。v2 历史格式失败仍为失败且未评审。历史五次总体状态冲突是移除冗余表达的动机，不是五个已修复的实验样本。本轮不授权真实重跑、不推断成功率提高、不建立 v3 模型质量结论。人工评分仍为 0%。

## 影响

模型不再重复计算确定性总体状态，但仍可能生成不一致条目、无据文本或非法 JSON，严格拒绝继续生效。后续模型质量比较需要另行授权的开发评估和新版本产物。冻结 v2 结果始终标明为历史 v2 结果。
