# ADR 0020：从快照派生不可变 GitHub 证据链接


- 状态：已接受
- 日期：2026-10-20

## 背景

正式证据已经带有稳定的应用内 `project://` 定位符和精确原文行号；GitHub 导入也已持久化 Commit 与逐文件快照来源，但用户还不能打开对应的不可变远端原文。链接到分支会随分支推进而漂移；把 GitHub URL 复制到每条证据中则会重复保存可派生的供应商数据并引入迁移。

## 决策

资料列表和详情响应根据该来源最近一次非 `deleted` 的快照文件记录，派生可空的 `git_url`。正式图谱、搜索与问答证据从同一个固定 Commit 文件 URL 派生链接，并追加 GitHub 从 1 开始、包含两端的行号片段。路径进行 URL 编码，但保留 `/` 分隔符。

持久化的 `project://` URI 继续作为应用内规范定位符；`git_url` 只是可选的外部便捷链接，不写入来源或证据表。本地来源以及缺少可用快照来源的导入来源返回 `null`。远端文件后来被删除时，来源及证据链接到它最后一次仍存在的快照。仓库坐标变化时，使用当前规范 GitHub remote 与历史 Commit SHA、路径组合链接。

## 影响

- 证据打开固定 Commit 和精确行号，不会随分支漂移。
- 不需要数据库迁移或改写证据；快照历史继续作为事实来源。
- 资料页、图谱详情、搜索结果和问答引用使用一致的来源行为。
- 私有仓库链接仍要求浏览器用户拥有 GitHub 访问权限；后端令牌不会进入 URL 或响应。
- 强制推送可达性、自动证据失效、Issue、Pull Request 和其他 Git 供应商不在本切片范围内。

## 评估过的替代方案

- 链接默认分支：证据会漂移，因此不采用。
- 在每条来源/证据记录上持久化 URL：会重复快照可派生数据，并使仓库改名更复杂，因此不采用。
- 用 GitHub URL 取代 `project://`：本地来源和应用内导航仍需要与供应商无关的定位符，因此不采用。
