# ADR 0009：显式构建正式知识语义索引


- Status: Accepted
- Date: 2026-10-18

## 背景

关键词检索能精确定位代码标识符和原文字面内容，但不能召回表达不同、含义相近的问题。项目已使用 PostgreSQL/pgvector，需要在不影响知识确认事务、不隐式调用外部模型的前提下增加可验证的语义召回。

## 决策

为正式实体增加独立的 `knowledge_embeddings` 表，保存实体名称、类型、摘要和证据摘录合成文本的 SHA-256、嵌入模型、固定 1024 维向量及项目/用户作用域。迁移版本为 `20261018_0006`。

嵌入服务采用后端可配置的 OpenAI-compatible `/embeddings` 接口，不绑定具体供应商。用户通过 `POST /api/v1/projects/{project_id}/embeddings/rebuild` 显式生成或刷新索引；内容哈希和模型未变化的记录直接复用。知识确认不调用嵌入服务，索引失败不回滚正式知识。

`GET /api/v1/projects/{project_id}/search?mode=vector` 为查询文本生成同模型向量，并使用 pgvector 余弦距离进行精确 Top K 检索。结果继续返回正式实体及原文证据，同时提供相似度、已索引数和可检索实体数。关键词模式保持原行为；混合排序、关系得分和问答仍不在本切片内。

## 影响

- 私有知识只会在用户显式更新索引或执行语义搜索时发送给所配置的嵌入服务。
- 更换模型、维度或实体内容后必须重建索引；当前数据库结构固定为 1024 维。
- 当前语料规模使用精确余弦检索，不建立 HNSW/IVFFlat 近似索引，优先保证可复现排序。
- SQLite 测试使用相同持久化结构并在 Python 中计算余弦相似度；真实 PostgreSQL 验收仍必须验证 pgvector 运算。

## 评估过的替代方案

- 在知识确认时自动生成向量：会把外部服务故障引入正式写入事务，未采用。
- 将供应商固定为 DeepSeek：候选抽取接口与嵌入接口职责不同，也不应假设同一供应商提供两者，未采用。
- 立即加入混合检索和 Agent：会扩大不可独立验收的范围，留给后续切片。
