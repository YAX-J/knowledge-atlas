# ADR 0030：解析有界仓库内 Java 静态导入调用

[English](0030-java-static-import-calls.md)

- 状态：已接受
- 日期：2026-10-22

## 背景

Java V1 索引忽略静态导入，常见工具方法的未限定调用无法定位到仓库内目标。阶段四继续扩展源码分析，同时不执行构建，也不把派生关系视为已审核知识。

## 决策

- 将显式与通配静态导入和类型导入分开索引。在既有用户/项目/仓库及字节边界内，把未限定调用解析到其他 ready 来源中的静态方法候选。不解析静态导入的嵌套类型或字段。
- 当前/继承成员名称保守阻止导入回退，即使参数数量不符。成员查找不完整也阻止回退。同名显式静态导入阻止通配导入，包括显式所属类型缺失的情况。限定 `this`/`super` 调用永不回退导入。
- 复用有界继承方法查找、签名抑制、参数数量/可变参数筛选、来源版本歧义、确定性目标 ID/排序和输出上限。可返回继承的类静态方法；接口静态方法不继承。
- 排除非静态和私有方法。跨当前包的导入类型必须为 public；跨该包声明的方法必须为 public（包括接口方法的隐式 public）。完整 Java 类型/访问/重载求解不在此有界子集内。
- API 字段与持久化不变。静态导入链接的 `cross_file_calls[].receiver` 为标记 `import static`，不是源码接收者表达式。目标保留原方法符号、路径及行号；不完整/歧义结果不代表编译器认证调用。不增加编译器、依赖、迁移、外部请求或正式图谱写入。

## 影响

已有大纲可把工具方法调用追溯到原声明。导入冲突与不可变版本保持歧义；缺失依赖和不支持语法不会产生虚构目标。保守成员优先可能省略完整编译器能够解析的调用。阶段四及真实供应商/原生 PostgreSQL 验收仍是独立工作。

验收使用 `tests/test_java_static_imports.py` 与 [V1 回归命令](../JAVA_ANALYSIS_V1.zh-CN.md)，再运行完整后端测试及 `git diff --check`。夹具覆盖原 ID/行号、导入优先级、可访问性、重载、继承静态方法、截断及 API 已解析来源/仓库/项目隔离。
