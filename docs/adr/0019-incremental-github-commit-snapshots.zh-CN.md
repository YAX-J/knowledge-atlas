# ADR 0019：持久化增量 GitHub Commit 快照


- 状态：已接受
- 日期：2026-10-20

## 决策

每次成功的显式 GitHub 同步都持久化一份不可变仓库快照，保存解析后的 ref、commit/tree SHA、Commit URL/消息/时间、有界结果标记、变更计数，以及每个入选支持 blob 的文件记录。仓库同时保存 GitHub 稳定的 provider repository ID，并采用 GitHub 返回的规范 owner/name，使上游仓库改名不会被静默当成另一个身份。

同一 ref 使用紧邻的上一份快照作为增量基线。路径和 blob 均未变化时直接复用既有来源，不再下载 blob；相同 blob 出现在其他路径时也复用来源，其中唯一消失的旧路径会报告为重命名。完整新 tree 中缺失的旧路径会记录为删除。连续重复同步同一 Commit 时直接复用已持久化快照，不再读取 tree 或 blob。

只有递归 tree、50 文件上限与 20 MiB 预算均未截断时，删除对账才是完整的。远端删除不会物理删除不可变来源、解析分块、已审核知识或证据，而会保留为快照历史，交由后续时序治理决定其有效性。

## 影响

- 分支前进时只下载新增或变化的 blob，同时保留既有校验、去重、任务和证据链路。
- 快照历史通过用户/项目/仓库范围的只读接口查询。
- 可唯一判断的文件重命名会更新来源的当前展示路径，旧路径仍保留在上一快照中。
- 复制文件与存在歧义的同 blob 移动只复用内容，不猜测为重命名。
- 本切片不实现 Webhook、轮询、force-push 祖先分析、来源/知识失效、不可变行链接、完整 Commit diff 导入、Issue 或 Pull Request。
