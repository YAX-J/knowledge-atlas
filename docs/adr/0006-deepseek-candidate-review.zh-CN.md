# ADR 0006 显式 DeepSeek 候选提取与证据审核


- 状态：Accepted（已接受）
- 日期：2026-10-17
- 后续扩展：[ADR 0007](0007-confirmed-postgresql-graph.zh-CN.md) — 确认候选现已写入 PostgreSQL 正式图谱表。

## 背景

用户已报告本机 PostgreSQL 17/pgvector 导入、重复复用、重启保留和自动解析通过，授权继续开发，并选择 DeepSeek API。PostgreSQL 竞争/恢复故障注入仍待专项验证。在正式图谱存储实现之前，需要为模型输出提供可观测的审核边界。

## 决策

- 使用小型 HTTP 适配器访问 DeepSeek 官方聊天接口，以 JSON 输出配合本地 Pydantic 校验。地址、模型、超时可配置，密钥只在后端环境配置中保存。按当前 [官方文档](https://api-docs.deepseek.com/) 默认使用 `deepseek-flash`；测试模拟响应，不代表真实模型已验收。
- 仅通过来源上的显式同步操作调用模型，不在上传或解析 Worker 中自动调用。限制输入/输出，不自动重试付费调用。前端超时不表示服务端或模型请求已取消。
- 使用 `knowledge_candidates` 任务类型，历史 `knowledge_extraction` 仍只解析。根据来源、提示版本和候选局部 ID 派生稳定任务/候选 UUID。来源锁串行化认领，执行 UUID 保护结果写入，过期任务可显式重试。成功来源/提示版本结果在修改模型配置后也复用，暂不支持强制重新提取。
- 校验固定类型、唯一局部 ID、同批关系端点和所属范围内原文分块的逐字摘录。后端计算引用行号。整批通过后，以同一事务保存待审核候选和任务成功状态，否则不保存部分候选。
- 复用 `candidate_knowledge` 暂存实体/关系和证据元数据，在候选 payload 中记录模型与提示版本。新增 `review_events` 保存操作者、时间和前后值。审核状态与事件同一事务提交，项目锁和条件更新串行化决策。相同重复请求幂等，已处理决策发生变化时冲突，确认关系要求两端实体已确认。
- 确认表示候选已通过审核，等待后续正式写入，不创建正式图谱节点、关系或时序版本。页面必须说明这一边界。合并、撤销、消歧、正式图谱写入、检索和 Agent 回答暂缓。ADR 0007 后续实现正式图谱写入；合并、撤销、消歧、检索和 Agent 回答仍暂缓。

## 影响

用户可以通过真实 API 和按资料展示的页面审核带原文证据的模型建议，模型不直接写入正式知识。精确摘录校验只证明定位准确，不证明语义正确；仍需要人工审核和真实模型质量评估。

迁移 `20261017_0004` 为增量变更；回滚会删除审核事件，保留候选/来源记录。本机服务与真实模型调用验收应与隔离测试、模拟浏览器夹具区分。大文件需要手动拆分；提取不排队、不自动分批、不提供心跳、不自动重试。中断的模型请求可能已计费，之后的显式重试可能再次计费。

## 评估过的替代方案

- 上传后自动提取：暂缓，以保持付费调用显式、解析可独立使用。
- 模型直接写图谱：拒绝，因为会绕过校验和证据审核。
- 正式图谱表尚未实现时将审核确认为图谱写入：拒绝，因为会错误表达完成状态，并掩盖后续一致性规则。
