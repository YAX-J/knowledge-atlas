# ADR 0086：逐批保存向量与显式恢复

状态：已接受。日期：2026-11-26。

## 决策

显式更新语义索引时，每批校验后的向量与该任务进度在同一事务提交。后续批次失败保留此前成功批次；读取状态或刷新页面不会重新调用供应商。只有用户再次明确更新时，才重新规划并复用原始实体归属、模型、维度和内容哈希全部匹配的向量，计算剩余或变化内容。

`EmbeddingRebuildRead` 增加 `remaining_count`、`completed_batches`；运行中或失败的任务也可带 `result`。数量表示本轮计划及已提交批次，不是实时全库覆盖率；独立索引状态接口继续报告当前范围覆盖。部分向量提交后立即可检索，界面明确说明覆盖可能不完整。

认领时取得项目锁并检查项目未归档。每批调用前续租，落库前在项目锁内检查执行 UUID。有效向量任务期间，项目归档返回冲突。被接手的旧执行器提交迟到结果时返回冲突。过期记录需要显式 `retry_interrupted=true` 才能接手。

## 后果与限制

不新增迁移，source head 仍为 0024。更新仍是同步请求。供应商成功但响应丢失、校验失败或提交失败的当前批没有可复用结果，显式重试可能重复计费；不承诺恰好一次。现有向量表只有一个实体的当前模型槽位，切换模型会逐批替换，查询按模型/维度过滤。原始实体和证据 UUID 不变，冻结实验和账本不变。

## 验证

原生 PostgreSQL 隔离迁移及最终 343 项回归通过，临时 schema 已清理，业务迁移标记保持 0023。用例覆盖后续失败保留成功批次、显式重试只算剩余、状态读取零调用、旧执行的迟到发布和归档保护。隔离桌面验收覆盖键盘焦点、部分进度与刷新。
