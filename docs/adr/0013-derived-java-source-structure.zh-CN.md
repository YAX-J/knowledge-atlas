# ADR 0013 在正式图谱之外派生有界 Java 源码结构

[English](0013-derived-java-source-structure.md)

- Status: Accepted
- Date: 2026-10-18

本记录中的跨文件限制已由 [ADR 0014](0014-bounded-cross-file-java-types.zh-CN.md) 扩展为有界顶层类型关系；同文件方法调用规则保持不变。

## 背景

Java 分块已经能够保留证据，但开发者还需要简洁的文件大纲和可导航的方法调用提示。若把解析器推断直接提升为已审核知识，会绕过现有证据与人工审核边界。

## 决策

- 为已解析 Java 来源提供 `GET /api/v1/sources/{source_id}/code-structure`。
- 根据不可变原文按需派生响应，不新增数据表，也不把派生符号和调用写入正式图谱。
- 返回带稳定标识和行号的类型、常规字段与方法符号，最多 200 个符号。
- 只报告未限定名或 `this.` 调用且名称能匹配同文件方法的关系。名称唯一时为 `resolved`，重载或同名冲突时为 `ambiguous`；同一行重复调用去重，最多 500 条。
- 候选抽取与人工审核仍是进入正式知识的唯一通道。

## 影响

桌面资料工作台无需迁移或模型调用即可展示有用的代码结构。对于不可变来源字节，结果保持确定性，并与已确认知识明确分离。

这不是 Java 语义解析，不解析接收者类型、静态限定调用、继承、依赖注入、跨文件符号、外部库或动态分派。非常规声明可能被遗漏，重载调用只标记为歧义。

## 评估过的替代方案

- 立即持久化独立代码图：暂缓，等仓库导入和跨文件标识规则确定后再做。
- 把解析结果直接提升为正式实体/关系：不采用，因为会绕过审核。
- 立即使用完整编译器或 tree-sitter：暂缓，等仓库级解析足以支撑该依赖时再采用。
