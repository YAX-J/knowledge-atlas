# ADR 0012 使用保留行号的有界 Java 源码导入

[English](0012-bounded-java-source-ingestion.md)

- Status: Accepted
- Date: 2026-10-18

## 背景

Markdown 到证据问答的链路已经具备扩展数据源的基础。第一段代码接入既要保持现有证据约束，又不能要求新增解析器运行时、仓库凭据或持久化模型。

## 决策

- 通过现有资料上传接口接收 UTF-8 `.java` 文件，使用 `source_type=java` 和 `code_parsing` 任务类型。
- 继续以 `SourceDocument`、`ProcessingTask` 和 `SourceChunk` 作为存储边界。重复复用限定在同一用户、项目、来源类型和内容 SHA-256 内。
- 使用确定性的本地结构解析器：在保持偏移量的前提下屏蔽注释和字面量，识别顶层 Java 类型及常规直接成员方法，并把精确的整行原文保存为 `code`、`type` 或 `method` 分块。
- 保留从 1 开始且包含两端的行号、内容哈希、标题路径和稳定分块 UUID。类型路径为 `[类型]`，方法路径为 `[类型, 方法]`。
- 解析完成后复用已有 Worker、手动任务执行、候选抽取/审核、图谱、检索和证据问答流程。

## 影响

Java 文件无需数据库迁移或第三方解析器即可进入现有证据链路。来源类型校验会阻止文件扩展名与提交类型选择不同解析器。

该解析器明确不是完整 Java AST，不承诺嵌套类型建模、重载签名、语义解析、调用图、仓库路径、Git URL、GitHub 导入或仓库增量同步。这些属于阶段四的后续切片。

## 评估过的替代方案

- 立即引入 tree-sitter：暂缓，等符号与调用图需求足以支撑依赖和语法版本维护时再采用。
- 解析时直接把代码符号写成正式图谱实体：不采用，正式知识仍应经过抽取和审核门槛。
- 在第一段代码切片中克隆仓库：暂缓，将认证、仓库生命周期和增量更新与单文件解析分离。
