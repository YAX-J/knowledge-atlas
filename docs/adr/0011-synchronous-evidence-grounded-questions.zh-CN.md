# ADR 0011 使用同步问答与受校验引用实现证据回答

- Status: Accepted
- Date: 2026-10-18

## 背景

项目已经具有可解释混合检索和正式证据，但还没有真实问答链路。第一版必须可审计、限制发送给外部模型的内容，并在回答质量尚未明确前避免过早设计持久化会话模型。如果一次性引入 LangGraph、流式响应和问答历史表，会模糊证据边界并扩大故障面。

## 决策

将 `POST /api/v1/projects/{project_id}/questions` 实现为同步且不持久化的操作。它复用现有混合检索，最多选取 5 个实体和 12 条正式证据，只把问题及这些证据发送给 DeepSeek，并要求严格 JSON 输出。一次回答最多引用 5 个证据 UUID；接口拒绝检索集合之外的引用，并且只返回模型实际引用的证据。

检索不到证据时，服务直接返回确定性的“不支持”回答，不调用回答模型。受支持回答必须包含引用；不支持回答必须说明缺少的信息。当前前端只展示本次结果，并明确提示不保存问答历史。

当前有界流程采用普通、确定性的服务编排。LangGraph、流式响应、工具规划、多轮记忆、重排和问答持久化，等到出现明确需求后再引入。

## 影响

- 每条返回引用都是生成前选定、当前可见的正式证据。
- 混合问答依赖已配置的嵌入服务和显式更新的语义索引；检索到证据后还需要 DeepSeek 密钥。
- 供应商失败不会留下半成品问答记录，因为当前不写入问答数据。
- 返回的回答 UUID 只标识本次响应，之后不能按该 ID 查询。
- 真实供应商质量、提示注入抵抗、延迟和包含图关系的代表性召回仍需在模拟测试之外专项验收。

## 评估过的替代方案

- 立即持久化问答：在保留策略、隐私、版本和过期引用语义明确前不采用。
- 第一版即引入 LangGraph：当前流程是线性的，不会因此获得可观测的新能力，暂不采用。
- 允许模型自行检索或引用任意 ID：应用层无法强制校验引用归属，不采用。
- 无检索结果时仍生成回答：会允许模型使用未提供的知识，不采用。
