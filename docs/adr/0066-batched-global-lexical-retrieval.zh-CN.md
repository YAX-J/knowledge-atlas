# ADR 0066 使用全局语料统计的分批词法检索


- 状态：已接受
- 日期：2026-10-30
- 取代 ADR 0044/0051 中的扫描/证据预算和协议标识；分词、BM25 公式、显式模式及证据边界保持。

## 决策

将 BM25 前 1000 个实体窗口替换为按名称/UUID 排序的按键分页，每批投影读取 200 个实体，单请求显式预算 50,000 个实体。每批及最终实体读取都保留用户、项目、类型、有效时间和身份可见条件。全部已扫描文档（含空文档和无命中文档）共同贡献文档数、总词长、查询词的文档频率；扫描完成后统一打分，不将每批作为独立语料。

只为命中实体保留查询词频、长度和命中字段；全局统计完成后以有界 Top K 堆选择最终实体。排序不读取来源正文。证据 SQL 使用按规范实体分区的行号窗口，每实体最多 32 条引用加一条省略探针，每条最多 2000 字符；每实体排序文本仍最多 4000 字符，字段顺序为名称/别名、摘要、可选来源位置、证据。名称/UUID 游标处理重名实体。不新增供应商请求、正式图谱写入、持久化检索索引或迁移。

协议为 `mixed-bm25-v2` / `mixed-bm25-source-v2`。RRF 使用 v2 BM25，新实验清单记为 `bm25-vector-rrf-v2`。Schema/类型继续接受旧协议值，不重写冻结语料、实验结果或历史分数。字面关键词和固定混合模式保持原行为。

新增 `lexical.batch_size`、`evidence_limit_per_entity`、`matched_count`、`results_truncated`。原 `entity_limit` 现返回 50000，`scanned_count` 是累计扫描数。`truncated_reasons` 仍返回 `entity_limit`、`evidence_limit`、`text_limit`，表达排序输入省略，独立于匹配数超过 Top K 的结果截断；总 `truncated` 是两者并集。RRF 的词法元数据描述词法候选池，不是最终融合结果。

## 影响

可召回第 1000 条之后的唯一匹配，不一次保留全量原文，也不逐实体执行 SQL。扫描工作和命中统计内存仍随语料规模增长；5 万条上限及每实体文本/证据预算仍可能省略相关输入，必须明确展示。分页在单次同步请求内进行，不是持久化、可跨请求恢复的检索任务。语句间并发修改不获取数据库快照，不承诺可重复读隔离。全文/ANN 索引、缓存失效、真实供应商实验和人工评分另行推进，不能将 v1 的延迟/质量数字归于 v2。

## 验证

用户已选择 Agent 执行。2026-10-30 实际结果：

- 聚焦词法/来源/检索/读取性能/问答/实验回归：55 项通过。
- 完整后端，`KA_NATIVE_COMPILERS=1`：730 项通过，7 项显式外部/原生专用用例跳过；应用语句覆盖率 95.18%，超过 90% 门槛。
- 原生 PostgreSQL 17.10 / pgvector 0.8.7：运行器自有 schema 中 152 项通过，含迁移升级/降级/再升级。临时 schema 已清理，应用迁移标记未变。
- 前端：16 文件、116 项测试通过，配置范围语句覆盖率 68.66% / 行覆盖率 73.42%；类型检查和生产构建通过。本轮没有可见界面变化，因此无需浏览器走查。
- 修改的 Markdown 中 266 个本地链接目标均存在；空白检查通过，冻结实验资产未变。

首次沙箱内 TestClient 运行停滞后已停止，同一虚拟环境的回归在沙箱外完成。旧的全批共享证据预算断言由每实体独立预算用例覆盖。没有真实供应商调用；这些结果验证正确性和集成，不代表 v2 延迟、生产容量或答案语义质量。
