# ADR 0036：从静态工厂调用推断有界 Java `var` 接收者

[English](0036-bounded-java-static-factory-var-receivers.md)

- 状态：已接受
- 日期：2026-10-23

## 背景

Java 分析 V1 可以解析显式类型局部变量和由构造器初始化的 `var`。常见仓库代码还会使用 `var value = Factory.create(...)`；即使同一已导入仓库快照中同时存在工厂声明及其返回类型，现有分析也只能看到工厂调用，不能解析后续对 `value` 的调用。

## 决策

为普通方法体局部 `var` 识别完整的“类型限定静态工厂调用”初始化表达式。复用仓库内类型/导入查找、实参数量筛选和继承方法候选。只有所有可访问的静态工厂候选都能解析到一个可访问的仓库内返回限定名，并且所有候选对该名称一致时，才推断接收者。

推断绑定从声明终止分号后生效，并沿用现有词法作用域、遮蔽、仓库、ready 状态与分析预算。工厂缺失、歧义、非静态、私有或返回外部类型时，绑定保持未知，因此继续阻止字段/类型回退。接口形状、持久化模型和正式图谱均不改变。

## 影响

系统无需执行构建或把派生结构写成已审核知识，就能把 `var value = Factory.create(...)` 之后的调用指向仓库内原方法符号。重复工厂/来源版本仍会通过后续歧义显式呈现，不会被静默选中。

这不是通用表达式或数据流推断。链式、强制转换、条件表达式、实例工厂、未限定名/静态导入工厂、头部绑定及重新赋值仍不支持；泛型替换、按实参类型选重载、外部 classpath 和运行时分派也不在范围内。

## 评估过的替代方案

- 使用完整 Java 编译器或语言服务器。暂缓，因为 V1 需要对上传快照保持确定性、无依赖和安全。
- 根据命名约定或被赋值变量名推断。拒绝，因为这会在没有源码证据时虚构接收者类型。
- 选择第一个匹配工厂重载或返回版本。拒绝，因为有界、不可变来源集合中可能合理存在歧义。
