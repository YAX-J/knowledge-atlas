# ADR 0033：将已保存的提交说明导入为证据来源


- 状态：已接受
- 日期：2026-10-22

## 决策

- 新增无请求体的显式 `POST /projects/{project_id}/repositories/{repository_id}/snapshots/{snapshot_id}/commit-source`，把本地保存的 GitHub SHA、UTC 提交时间与提交说明渲染为普通 Markdown。端点不请求供应商/模型，不自动解析、抽取或审核；既有 Worker 仍可消费新建的排队解析任务。
- 校验用户、未归档项目、仓库与快照归属；SHA 验证通过后才参与文件名。复用既有 UTF-8/大小限制、SHA-256 仓库/类型范围去重与项目行锁。复用时返回任务当前状态，缺失或不兼容映射重新走普通导入，不信任外作用域引用。
- 渲染内容不包含 ref、同步计数或可变仓库坐标；相同保存元数据跨 ref/改名重复导入复用来源，不同 Commit/仓库保持独立。空提交说明也生成明确占位及来源边界提示。
- 可回滚迁移 `20261022_0014` 仅为快照添加可空 `commit_source_id` / `commit_task_id` 外键（`SET NULL`）及来源索引。原提交/文件同步事实不变，只补充导入映射。降级删除映射而不删除来源/任务/分块；重新升级后导入可按字节去重。
- 为资料及正式图谱/搜索/问答证据派生当前规范 remote 的 `/commit/{sha}`。本地 Markdown 行号不是 patch 定位，不得伪造 GitHub `#L` 片段；保留应用内 `project://` 与普通证据校验。
- 桌面新增已保存历史面板：每页十项、加载/空/错误/重试、有界滚动、规范链接及显式导入/打开。应用请求序号屏蔽历史迟到响应；提交导入沿用上下文锁，刷新列表后打开原资料/任务并聚焦原文。

## 影响

提交说明可进入既有“解析 → 显式模型候选 → 人工审核 → 正式知识”流程，但它是提交作者的陈述，不证明实现正确性。不新增正式 Commit 实体或自动关系，不导入 patch/父历史，不实现轮询、Webhook 或完整 Git 历史。阶段四仍在进行。运行新应用前须应用迁移；临时验收脚本不会升级业务 schema。

2026-10-22 实际结果：28 项聚焦测试、333 项完整后端测试通过（新增 17 个用例），前端类型检查/构建通过；保留既有 Starlette/httpx 弃用警告。测试覆盖作用域/归档边界、确定性内容、复用/当前状态、缺失/外作用域映射恢复、大小限制、不可信说明、SQLite 迁移数据保留与往返、PostgreSQL 离线 SQL，以及模拟模型抽取 → 审核 → Commit 证据流程。模拟响应不证明真实模型质量。

本机 PostgreSQL 临时独立 schema 已通过迁移升级 → 降级 → 再升级，以及两种 ref 并发导入同一提交只生成一份来源/任务的验证。桌面验收使用独立 API/Vite 8001/5174 与公开合成夹具，不读取 GitHub、不调用真实模型，也不停止既有 8000/5173 服务。

桌面走查通过加载、注入的临时错误/重试、十项分页、空历史、长说明键盘滚动/可见焦点、导入/打开复用、手动解析为六个原文分块、规范 Commit 链接及切项目迟到响应清理。完整新增面板 axe-core 零违规；一个滚动裁切导致的对比度待确认项，在滚动到该行后复查通过。说明/正文相对面板的计算对比度为 5.34:1 / 14.28:1。就绪检查 PostgreSQL 为 `up`。验收后已删除任务专属 schema、临时脚本并关闭浏览器/API/Vite 会话；未升级或删除既有业务数据。
