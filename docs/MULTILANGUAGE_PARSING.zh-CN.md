## 已实现的范围

本地单文件、最多 50 份支持文件的文件夹上传、显式 GitHub 文件同步、手动解析和 Worker 共用来源类型注册表。保留 UTF-8、大小、空文件、路径和用户/项目/仓库隔离校验；去重按来源类型和字节哈希，不会跨语言复用。无需新增数据库迁移，head 仍为 `20261023_0015`。

| 来源类型 | 扩展名 | 结构能力 |
| --- | --- | --- |
| `markdown` | `.md .markdown` | 原标题/段落/列表/代码分块 |
| `java` | `.java` | 保持原 Java V1、符号身份及有界仓库内调用分析 |
| `python` | `.py .pyi` | 类、函数/方法、简单类属性，包含装饰器原文 |
| `javascript` | `.js .mjs .cjs` | 类、方法、字段、声明函数和具名变量绑定函数 |
| `jsx` | `.jsx` | 同 JavaScript，支持 JSX 语法 |
| `typescript` | `.ts .mts .cts` | 类/接口/类型别名、字段/属性、函数/方法 |
| `tsx` | `.tsx` | 同 TypeScript，支持 TSX 语法 |
| `go` | `.go` | 类型、结构字段、函数及接收者方法 |
| `c` | `.c .h` | 具名结构/联合/枚举、字段、函数定义/原型 |
| `cpp` | `.cpp .cc .cxx .hpp .hh .hxx` | 具名类型、字段、函数/方法及部分命名空间限定 |
| `csharp` | `.cs` | 类/结构/接口/记录等具名类型、字段/属性、方法/构造器 |

扩展名不区分大小写，`.h` 确定性视为 C；C++ 头文件请使用 `.hpp/.hh/.hxx`。不做文件内容猜测或全语法承诺。

## 原文、结构与检索

- 新语言使用固定版本的 Tree-sitter 与官方语言 wheel，语法随依赖安装，不在解析时下载、执行用户代码、加载工程依赖或调用模型。
- 所有原始行（包括空白和错误代码）按顺序完整分区；每块最多 120 行，内容是原文整行切片，SHA-256/UUID 确定。类型/函数边界优先，长函数可以分为多块。
- 大纲与代码符号检索共用 UUID 和行号；`type/field/method` 分别表示类型、字段/属性、函数/方法，保持旧接口兼容。检索命中携带 `language`，结构响应增加 `language` 与 `has_syntax_errors`。
- 每文件最多 200 符号、遍历最多 100,000 个语法节点，达到上限标记 `truncated`；检索仍最多扫描 100 份来源/20 MiB，默认返回 50、最多 100 个命中。
- 语法树包含错误时，结构/检索明确返回 `has_syntax_errors=true`；含错误的声明不作为可靠符号，其他局部结构可能保留。解析成功只表示原文可引用，不代表编译通过。不会把错误标记混成数量截断。
- 前端展示语言标签、语法错误警告、结构与精确分块；搜索结果可打开对应分页并聚焦原 UUID。GitHub 命中仍链接固定 Commit/行号。

## GitHub 旧快照

默认保持完整相同 Commit 的缓存短路。旧版本生成的完整快照可能没有扫描新支持的扩展名；勾选仓库卡片“重新扫描”，或发送 `{"rescan":true}` 到同步接口，即可重读同 Commit 的 tree，复用已知兼容 blob/任务并发现新增语言。仍受文件/字节预算约束，不删除历史资料、不自动生成正式知识。

## 限制与验证

新语言不解析跨文件调用、导入目标、类型推断、宏展开、泛型实例化或运行时行为；匿名/计算成员、复杂声明等可能省略。Java 保持独立的原有有界分析。所有结构均是派生资料，不是正式知识，也不会绕过人工审核。

新增聚焦测试：`cd backend; .\.venv\Scripts\python.exe -m pytest tests/test_multilanguage.py`。测试使用 SQLite 与模拟 GitHub；不代表真实 GitHub/模型质量或原生 PostgreSQL 专项验收。安装/升级依赖：在 `backend` 运行 `.\.venv\Scripts\python.exe -m pip install -e ".[dev]"`。
