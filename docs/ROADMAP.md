## 阶段四 代码与 GitHub 数据

工厂 `var` 进一步支持当前/继承静态成员与显式/通配静态导入的完整未限定名调用，按成员名称优先并要求返回限定名一致；类型限定名遮蔽和方法类型参数返回继续保持未知。该阶段四扩展已集成，见 [ADR 0037](adr/0037-unqualified-java-factory-receivers.zh-CN.md)。

Java V1 现可从完整 `Type.factory(...)` 静态工厂初始化表达式推断普通方法体局部 `var`：只有可访问的仓库内候选对一个可解析返回限定名一致时才继续解析后续接收者调用；其余情况保持未知并阻止回退。该切片不包含通用表达式/数据流推断，见 [ADR 0036](adr/0036-bounded-java-static-factory-var-receivers.zh-CN.md)。

图谱、搜索和问答引用可按证据 UUID 跳回本地精确分块，自动翻页和聚焦/高亮，补齐 Markdown/Java/提交说明等已保存来源的核验入口；不改变正式知识语义或引入新阶段，见 [ADR 0035](adr/0035-exact-evidence-source-navigation.zh-CN.md)。

## 建议十二周安排

| 周次 | 重点 | 可验收结果 |
| --- | --- | --- |
| 1 | 后端骨架、数据库和领域模型 | 健康检查与数据库迁移 |
| 2 | 项目、资料和任务接口 | 基础 CRUD 与上传任务 |
| 3 | Markdown 解析和分块 | 可查看原文块及来源位置 |
| 4 | LLM 结构化抽取 | 通过 Schema 校验的候选知识 |
| 5 | 人工确认和实体消歧 | 候选知识可确认与合并 |
| 6 | PostgreSQL 图谱写入 | 前端展示真实图谱数据 |
| 7 | 关键词与向量检索 | 两路检索服务可对比 |
| 8 | 图关系检索和融合排序 | 混合检索返回组成得分 |
| 9 | 证据问答 Agent | 回答可追溯到原文 |
| 10 | 代码或 GitHub 导入 | 至少接入一个真实仓库 |
| 11 | 时序知识、实验和测试 | 历史查询与对比结果 |
| 12 | 部署、论文和答辩准备 | 可复现演示环境和材料 |

## 风险控制

| 风险 | 控制方式 |
| --- | --- |
| 功能范围过大 | GitHub、高级治理和报告放在基础闭环之后 |
| 抽取结果不稳定 | 固定 Schema、规则校验、置信度和人工确认 |
| 图关系查询成本上升 | 限制深度和结果量、添加索引并用真实数据评估；必要时再考虑独立图数据库 |
| 演示依赖外部模型 | 保留固定测试数据和可切换的 Mock 模式 |
| 图谱数据过多导致页面卡顿 | 按中心节点和深度加载，限制可见节点数 |
| 论文创新点不明确 | 围绕关系检索、时间过滤和证据准确率设计实验 |

## 最终完成定义

项目达到以下条件才视为毕业设计核心功能完成：

- 能从至少两类真实来源构建个人开发知识。
- 知识图谱可编辑，并能回到原始证据。
- 问答融合至少三种检索信号。
- 回答包含可核验来源，证据不足时拒绝给出确定结论。
- 至少展示一组技术知识的历史替代过程。
- 有可复现的基线对比、实验数据和评价指标。
