# Knowledge Atlas 开发路线与验收标准

路线以“先完成端到端闭环，再扩展数据源和高级能力”为原则。本机 Markdown 到证据问答流程已由用户验收；阶段四已经开始，本地 Java 源码上传、结构分块、来源结构视图、带本地仓库身份与仓库内相对路径的单文件/文件夹上传、有界跨文件继承/实现与直接类型/字段接收者方法关系，以及规范化 GitHub remote 身份登记已实现，下一步是验收本轮能力后接入实际 GitHub 内容/Commit 导入。

## 当前基线

已完成：

- 项目定位、文献综述和开发步骤材料。
- 知识图谱工作台视觉原型。
- Vue 3 Mock 前端。
- 节点浏览、证据展开、筛选、时间轴和模拟问答。
- 桌面端界面。
- FastAPI 应用、健康检查、请求 ID 和统一错误结构。
- 项目、Markdown/Java 来源和排队任务接口。
- SQLAlchemy 领域模型、Alembic 初始迁移和 Docker Compose 配置。
- 后端接口测试。
- 可显式执行的 Markdown 解析、持久化分块与行号查询。
- 相同项目重复上传复用、任务幂等执行和失败重试。
- 前端真实项目创建/列表、资料上传/列表、解析/重试和原文分块分页。
- 可选后台 Worker、执行租约、中断接手和重试次数上限。
- DeepSeek 候选提取适配、固定输出/证据校验、候选查询和审核页面/接口（真实模型待验收）。
- 确认候选写入 PostgreSQL 正式实体、关系和证据，项目图谱与实体/关系详情只读接口及前端页面。
- 已确认实体的关键词检索基线与证据结果，支持名称/摘要/摘录匹配、排序、类型/时间过滤和详情/邻域跳转。
- 已确认实体的显式 1024 维语义索引与 pgvector 余弦检索，支持索引复用、类型/时间过滤、证据结果和前端模式切换。
- 关键词、向量与可见一跳关系的固定权重混合检索，返回归一化组成得分与关系解释。
- 同步、非持久化的真实证据问答，严格校验模型引用并在前端展示原文与实体跳转。
- 本地 Java 文件上传、`code_parsing` 任务、顶层类型/常规直接成员方法的精确行号分块，以及桌面端 MD/JAVA 展示。
- 按需派生的 Java 类型/字段/方法大纲、有界同文件调用提示、仓库内跨文件 `extends`/`implements` 目标及直接类型/字段接收者方法调用，不写入正式图谱。
- 桌面端分别提供单文件与文件夹上传；文件夹最多提取 50 份 Markdown/Java 文件并顺序上传，保存规范化相对路径，单份失败不回滚其他成功资料。
- 文件夹导入按项目、`local_folder` 类型和根目录名解析稳定仓库 UUID，来源保存仓库内相对路径；去重与跨文件类型解析不会越过仓库边界。
- GitHub HTTPS、SCP 风格 SSH 与 `ssh://` remote 可登记为项目范围的规范化仓库身份，可选关联已有本地文件夹仓库，并在桌面端仓库列表展示；登记不访问 GitHub 或拉取内容。

尚未完成：

- 本地 PostgreSQL 中的 Worker/API 并发与租约恢复专项验证；图谱重复确认并发已在临时 schema 中通过。
- 真实 DeepSeek 抽取质量验收与实体消歧。
- 真实证据问答质量、提示注入和延迟验收。
- 问答历史/多轮会话、历史/替代可视化、实验数据和部署验证。

当前数据库方案只使用 PostgreSQL/pgvector，Neo4j 按需延后，见 ADR 0005。节点、关系、证据、语义向量表、真实图谱、三路混合检索和同步证据问答已实现（ADR 0007、0009、0010、0011）；实体消歧、多轮问答和问答持久化仍待开发。

## 阶段一 基础工程（基础流程已由用户验收）

目标：建立可持续开发的前后端工程和本地依赖环境。

交付物：

- FastAPI 项目骨架和健康检查接口。
- PostgreSQL/pgvector 的 Docker Compose 配置。
- 环境变量示例、统一日志和错误结构。
- 项目、资料、任务和知识候选的基础表结构。
- 前端 API 层、加载状态和错误状态。

当前已完成前端项目/资料 API 接入及其加载、空数据、错误和重试状态；用户已报告 PostgreSQL 17/pgvector、本机启动、上传解析、重复复用、重启保留和 Worker 自动解析通过；并发竞争及租约故障注入仍需专项验收。默认使用原生本地安装，Docker Compose 为可选方案。

验收标准：

- 前后端可以分别启动。
- 后端可以连接 PostgreSQL。
- `GET /api/v1/health/ready` 返回各依赖状态。
- 前端能通过 API 创建并查询一个项目。

## 阶段二 Markdown 知识闭环（核心链路已实现，待真实验收）

目标：完成第一条真实端到端流程。

交付物：

- Markdown 与 TXT 上传。
- 按标题、段落和列表分块并保留层级。
- 内容哈希、重复导入检测和任务状态。
- 固定 JSON Schema 的知识抽取。
- 候选实体与关系确认页面。
- 已确认知识写入 PostgreSQL 节点、关系和证据表。

验收标准：

- 上传一篇 Markdown 后能够生成候选实体和关系。
- 每条候选知识都能定位到原文片段。
- 低置信度结果不会自动进入正式图谱。
- 用户确认后，前端图谱展示真实 API 数据。

当前已实现显式 DeepSeek 候选提取、证据校验、审核页面/接口，以及确认候选写入正式节点/关系/证据表和真实项目图谱展示。PostgreSQL 17.10 临时 schema 已通过图谱迁移、证据读取和并发重复确认；测试使用模拟响应，真实模型调用、原生数据库浏览器验收与真实数据质量仍待验收。

## 阶段三 检索与证据问答

当前已完成关键词、向量和一跳图关系三路基线，以及同步证据问答：问答最多使用 5 个检索实体与 12 条正式证据，严格限制并校验最多 5 个引用；无证据时不调用回答模型。前端提供证据不足、错误、统计、引用和实体跳转状态，当前不保存历史。真实嵌入服务和原生 pgvector 已通过 7 个实体的浏览器冒烟；包含关系的代表性数据、中文分词、权重调优与真实 DeepSeek 问答质量仍待验收，见 ADR 0008、0009、0010、0011。

目标：让系统基于个人资料回答问题并提供可核验证据。

交付物：

- PostgreSQL 关键词检索。
- pgvector 语义检索。
- PostgreSQL 一跳和限定关系查询。
- 固定权重的结果归一化与融合。
- 同步检索、证据核验和回答流程；LangGraph 留待多步工具规划出现时再评估。
- 答案证据面板和证据不足状态。

验收标准：

- 代码标识符问题能够通过关键词精确命中。
- 相似问题能够通过向量检索召回。
- 决策与实现关系能够通过图查询返回。
- 回答引用的每条证据都真实存在。
- 删除证据后，系统不能继续引用该证据回答。

## 阶段四 代码与 GitHub 数据

状态：进行中。已完成不依赖第三方解析器的本地 Java 基线：UTF-8 `.java` 上传、仓库范围去重、精确原文分块、类型/字段/方法大纲、未限定名/`this.` 同文件调用提示，以及最多 100 份同仓库已解析来源内按包和导入解析的跨文件 `extends`/`implements` 与直接类型/字段接收者方法调用；桌面端提供单文件与文件夹入口，文件夹最多导入 50 份支持文件、解析本地仓库身份、保存仓库内相对路径并保留部分成功结果。项目还可规范化登记 GitHub HTTPS/SSH remote，并将其关联到本地仓库身份或保存为仅远程身份。派生结构不进入正式图谱，remote 登记也不会访问 GitHub。完整 AST/语义解析、局部变量/参数/继承方法分派、provider ID 与仓库重命名跟踪、GitHub 内容/Commit 导入、Git URL 证据和增量同步仍未实现，见 ADR 0012、0013、0014、0015、0016、0017。

目标：将知识来源从文档扩展到真实开发活动。

交付物：

- Java、Python、JavaScript 或项目主语言的代码结构解析。
- 文件、类、函数、方法和调用关系。
- GitHub 仓库、README、Commit、Issue 和 Pull Request 导入。
- 代码行号和 Git URL 证据定位。
- 增量更新，只重新处理变化内容。

验收标准：

- 导入一个中等规模仓库后可按文件和符号查询。
- 技术决策能够追踪到代码实体或 Commit。
- 重复导入不会创建重复来源和知识节点。

## 阶段五 时序知识与治理

目标：完成论文题目中的时序能力，并增加知识质量控制。

交付物：

- `valid_from`、`valid_to`、`status` 和 `SUPERSEDES`。
- 当前知识和指定时间点历史知识查询。
- 新旧结论的补充、冲突和替代候选。
- 冲突、证据缺失、重复和孤立知识检测。

验收标准：

- 能够展示至少一条完整的知识替代链。
- 查询当前状态不会混入已失效结论。
- 查询历史时间点能够返回当时有效结论。
- 治理检测只生成建议，不自动修改正式图谱。

## 阶段六 实验与交付

目标：形成可复现的实验结果和完整答辩材料。

交付物：

- 关键词检索基线。
- 向量 RAG 基线。
- 知识图谱混合检索实验组。
- 测试问题、标准证据和标准答案数据集。
- 可复现的本机原生服务演示环境，可选 Docker Compose。
- 架构图、流程图、功能截图和实验图表。

评价指标：

- Top K 证据召回率。
- 答案正确率。
- 来源引用准确率。
- 跨文档关系问题正确率。
- 历史决策追溯正确率。
- 平均响应时间。
- 用户可解释性评分。

## 建议十二周安排

| 周次 | 重点 | 可验收结果 |
| --- | --- | --- |
| 1 | 后端骨架、数据库和领域模型 | 健康检查与数据库迁移 |
| 2 | 项目、资料和任务接口 | 基础 CRUD 与上传任务 |
| 3 | Markdown 解析和分块 | 可查看原文块及来源位置 |
| 4 | LLM 结构化抽取 | 通过 Schema 校验的候选知识 |
| 5 | 人工确认和实体消歧 | 候选知识可确认与合并 |
| 6 | PostgreSQL 图谱写入 | 前端展示真实图谱数据 |
| 7 | 关键词与向量检索 | 两路检索服务可对比 |
| 8 | 图关系检索和融合排序 | 混合检索返回组成得分 |
| 9 | 证据问答 Agent | 回答可追溯到原文 |
| 10 | 代码或 GitHub 导入 | 至少接入一个真实仓库 |
| 11 | 时序知识、实验和测试 | 历史查询与对比结果 |
| 12 | 部署、论文和答辩准备 | 可复现演示环境和材料 |

## 风险控制

| 风险 | 控制方式 |
| --- | --- |
| 功能范围过大 | GitHub、高级治理和报告放在基础闭环之后 |
| 抽取结果不稳定 | 固定 Schema、规则校验、置信度和人工确认 |
| 图关系查询成本上升 | 限制深度和结果量、添加索引并用真实数据评估；必要时再考虑独立图数据库 |
| 演示依赖外部模型 | 保留固定测试数据和可切换的 Mock 模式 |
| 图谱数据过多导致页面卡顿 | 按中心节点和深度加载，限制可见节点数 |
| 论文创新点不明确 | 围绕关系检索、时间过滤和证据准确率设计实验 |

## 最终完成定义

项目达到以下条件才视为毕业设计核心功能完成：

- 能从至少两类真实来源构建个人开发知识。
- 知识图谱可编辑，并能回到原始证据。
- 问答融合至少三种检索信号。
- 回答包含可核验来源，证据不足时拒绝给出确定结论。
- 至少展示一组技术知识的历史替代过程。
- 有可复现的基线对比、实验数据和评价指标。
